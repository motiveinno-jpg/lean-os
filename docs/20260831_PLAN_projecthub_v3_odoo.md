## 1. History — 그리고 왜 '싹 무시'인가

지금 프로젝트 메뉴는 **표(템플릿) 중심**이다: 프로젝트 안에 '회의·결정', '할 일·진행', '매출 흐름' 같은
표를 여러 개 만들고, 각 표가 칸·그룹을 커스텀한다. 유연하지만 —
- 일 하나(태스크)가 1급 시민이 아니라 "표의 한 줄"이다. 체크리스트·하위 할 일·댓글·반복·앞뒤 순서
  같은 **일의 속성**이 표 구조에 눌려 자라지 못했다.
- 표마다 문법이 달라 "지금 뭘 해야 하나"가 프로젝트를 열어봐야 보인다. 전체 화면이 안내판이 아니라 목록이다.
- Odoo 가 파는 핵심 — "포스트잇처럼 붙이면 파이프라인이 정리된다"(칸반 우선), 마일스톤·예산·수익성이
  프로젝트 얼굴에 붙어 있는 것 — 이 구조적으로 안 나온다.
- (참고) 오늘 다른 PC 에서 기획 v2.6 '개편 1단계'가 배포 중(모티브 게이트) — 이 v3 기획은 그 방향까지
  포함해 **사장님이 고르는 상위 기획**이다. v3 채택 시 v2.6 은 흡수/중단을 그때 정한다.

## 2. 자문자답

① **무엇을 기준으로 판단되어야 하는가** — 화면의 단위는 표가 아니라 **할 일(태스크)** 이다. 프로젝트의
  건강은 사람이 남긴 **상태 보고(순항/주의/지연)** + 숫자(지연 건수·예산 소진·마일스톤 D-day)로 판단한다.
② **사용자는 왜 이 메뉴를 여는가** — (a) 내가 오늘 할 것 (b) 프로젝트들이 지금 괜찮은가 (c) 이 일의
  다음 단계. 세 질문이 각각 첫 화면이 된다: 내 할 일 · 전체(카드) · 칸반.
③ **반대 경우** — 표가 꼭 필요한 일(청구 회차, 광고 지표)은? → '목록 보기'가 표를 대체하고,
  돈 흐름은 현황 탭의 돈 패널(견적·계약·전표 자동 연동)로 옮긴다. 표 커스텀 칸이 필요한 경우를 위해
  사용자 지정 속성(칸 추가)은 남긴다 — 단 태스크의 속성으로.
④ **자동으로 못 푸는 것** — 상태 보고(순항/주의/지연)는 사람이 쓴다. 숫자는 옆에 자동으로 붙는다.
  수익성 숫자는 오너뷰가 자동으로 잇는다(견적→계약→계산서→수금, 지출 전표) — Odoo 는 타임시트로
  풀지만 우리는 장부가 이미 있다. **타임시트는 안 만든다**(직원들에게 시간 기록을 시키는 문화 비용 > 효익).

## 3. 결정 (109~117)

- **결정 109 — 단위 교체**: 표(project_boards) 중심 → **프로젝트 › 할 일(task)** 중심. 할 일은
  단계(stage)·담당(여럿)·마감·태그·우선순위·체크리스트·하위 할 일·첨부·댓글(기록)·반복·앞뒤 순서·
  마일스톤 연결을 **속성으로** 가진다. AS_IS 표의 줄 ▶ TO_BE 태스크 카드. 기존 데이터는 표별 이관
  스크립트(표 한 줄 → 태스크 하나, 그룹 → 단계)로 옮긴다 — 마이그레이션은 구현 단계에서 결정.
- **결정 110 — 첫 화면 = 전체 카드**: 프로젝트마다 카드 하나 — 상태 신호등(사람이 쓴 최신 상태 보고),
  진행률(완료/전체), 다음 마일스톤 D-day, 예산 게이지(지출 전표 합/예산), 담당 아바타, 지연 배지.
  카드가 안내판이다 — 눌러야 아는 화면 금지(건수 알림 드릴다운 규칙 준수).
- **결정 111 — 보기 5종** *(→ 결정 118로 개정)*: 칸반(기본) · 목록 · 간트 · 캘린더 · 현황.
  프로젝트 안 어느 보기든 같은 태스크를 본다. ~~다섯 개를 고정 탭으로 늘어놓는다~~ →
  1차 목업에 그렇게 그렸다가 사장님 지적("예전 형식을 따라간다, 모든 게 다 펼쳐져 있어 헷갈린다")으로
  버림 — 고정 탭 줄 자체가 옛 습성이었다.
- **결정 112 — 칸반이 입력이다**: 단계는 프로젝트마다 커스텀(+단계), 카드 빠른 추가(제목+Enter),
  끌어서 단계 이동. 카드에 보이는 것: 별(우선), 제목, 태그, 체크리스트 n/m, 하위 n, 댓글 n, 마감(지연 빨강),
  반복 ↻, 아바타. Odoo 칸반 문법 그대로, 이름은 순한국어.
- **결정 113 — 기록(채터) 통합**: 태스크마다 댓글+변경 로그가 한 줄기 타임라인. 팔로워가 알림 받는다.
  회의록 템플릿은 별도 화면 대신 "회의" 태그 + 기록으로 흡수(안건→결정→할 일 전환 버튼 유지).
- **결정 114 — 상태 보고(프로젝트 업데이트)**: 현황 탭 맨 위. 순항/주의/지연 + 한 줄. 전체 카드
  신호등의 유일한 출처. 안 쓰면 "보고 없음 n일" 로 회색 — 자동으로 색을 추측하지 않는다.
- **결정 115 — 돈 패널(오너뷰 강점)**: 현황 탭에 예산 vs 실제(견적·계약·계산서·수금·지출 전표 자동
  연결). Odoo 의 판매주문·청구서 발행 정책은 이미 있는 견적→계약→발행 흐름을 잇는 것으로 갈음.
- **결정 116 — 내 할 일**: 전 프로젝트 횡단 — 지연 / 오늘 / 이번 주 / 다음. 대시보드 위젯과 같은 원천.
- **결정 117 — 버린 것**: 타임시트·VoIP·고객 포털·평점 설문·이메일로 태스크 생성 —
  10인 회사 규모에 문화 비용이 효익보다 크다(벤치마킹은 덜어낸 버전으로 — 사장님 확정 취향).
  피벗/그래프 보기 분리, 커버 이미지, SMS 템플릿도 제외.
- **결정 118 — 하나씩 켠다 (2026-08-31 사장님: "모든 게 다 펼쳐져 있어 헷갈리고 불편하다.
  필요할 때마다 하나씩 추가하는 형태로")**: 프로젝트는 **칸반 하나로 시작**한다.
  · **보기**는 ＋보기 카탈로그에서 하나씩 추가(목록·간트·캘린더·현황) — 추가한 것만 탭으로 남고
    ✕로 뺀다. 대시보드 위젯 카탈로그와 같은 문법(이미 사장님이 승인한 패턴).
  · **기능**도 ＋기능에서 켠다: 마일스톤 · 예산·돈 · 상태 보고 · 반복 · 앞뒤 순서.
    끄면 헤더·카드·서랍·전체 카드 어디에도 안 보인다 — Odoo 도 이 기능들이 설정 토글이다.
  · 전체 화면 카드도 **켠 만큼만** 보인다: 막 시작한 프로젝트 카드는 이름+진행뿐, 기능을 켤수록 자란다.
  · 규칙: 새 프로젝트 기본값 = 칸반만·기능 0. 보기·기능 구성은 프로젝트 단위 저장(개인 아님 —
    팀이 같은 화면을 봐야 한다). 기존 데이터가 있는 기능은 꺼도 데이터를 지우지 않는다(숨김일 뿐).

## 3-2. 3차 — 공식 데모 영상 반영 (결정 119~123)

사장님이 영상(youtu.be/T45Jo3s_Pt4 · "Odoo Project - For efficient project management", 4:24)을 주며
재기획 지시. 자막 전문을 추출해 데모의 **일하는 흐름**을 분석 — 기능 목록 페이지엔 없던 것들이 나왔다.
(영상 시나리오: 극단이 뮤지컬 'Outrageous' 제작을 관리 — 프로젝트 생성→담당·기간·중요도·팔로워→
공개 범위 변경→외부 투자자 초대→칸반 단계 생성→태스크 신호등→드래그→간트 기한·종속→상단 바 허브→
자동화 규칙(태그→팔로워)→다음 활동(금요일까지 배우에게 전화)→타임시트→평점→대시보드)

- **결정 119 — 만들기가 한 장이다**: 새 프로젝트 = 팝업 한 장에서 이름·담당(PM)·기간·중요(★)·
  팔로워·공개 범위·외부 초대까지 정하고 시작한다. 영상의 첫 40초가 전부 이 폼이다 —
  만들고 나서 설정을 찾아다니게 하지 않는다. 전부 선택 입력(이름만 필수, 결정 118과 정합).
- **결정 120 — 공개 범위 + 외부 공유 (기능 토글)**: 프로젝트 단위 공개 범위(담당자만 / 회사 전체).
  '외부 공유'를 켜면 회사 밖 사람(투자자·거래처 담당)을 **한 명씩 초대**(보기 전용/댓글 가능) —
  영상의 투자자 Abigail. 결정 117에서 버린 '고객 포털'과 다르다: 포털 구축이 아니라 링크 초대 한 명.
  기존 전자계약 공유 링크 인프라를 재사용.
- **결정 121 — 카드 신호등 + 다음 활동**: ①태스크마다 **상태 점**(회색 보통 · 초록 순조 · 빨강 막힘) —
  단계와 별개로 "한눈에 어느 태스크가 어떤 상태인지"(영상 1:29). 카드에서 눌러 바꾼다.
  ②태스크마다 **다음 활동 한 줄**: "무엇을 · 누가 · 언제까지"(영상 3:09 — 금요일까지 데비에게 전화).
  체크리스트가 '전부'라면 다음 활동은 '지금 당장 하나'다. 카드에 배지(📞 금)로 보인다.
- **결정 122 — 상단 연결 허브 (상시)**: 프로젝트 헤더에 연결된 것들 칩 — 계약 2 · 전표 47 · 파일 12 ·
  회의 4. 누르면 그 목록으로(영상 2:07 "앱을 계속 오갈 필요가 없다"). 오너뷰는 장부·문서가 이미
  있으므로 자동으로 이어진다. ★결정 118 예외: 사용자가 만드는 기능이 아니라 이미 있는 데이터를
  이어 주는 것이라 토글 없이 상시 — 단, 데이터가 0건인 칩은 안 그린다.
- **결정 123 — 자동화 규칙 (기능 토글)**: "~하면 → ~한다" 한 줄 규칙(영상 2:46 — 태그 '조명' 붙으면
  Amy 를 팔로워로). 오너뷰식 예: 태그 '개발' → 이경원 팔로워 / 단계 '검토' 도착 → 대표에게 알림.
  트리거 2종(태그 붙음·단계 도착) × 액션 2종(팔로워 추가·알림)만으로 시작 — 자동화 기본구조
  (제안·통지는 자동, 확정·발송은 사람) 안에서 알림·팔로워까지만 자동.
- 영상의 타임시트(3:25)·고객 평점(3:37)은 결정 117 유지 — 다시 보되 다시 버림(문화 비용).

## 3-3. 4차 — monday.com 입력 결합 (결정안 124~127, 사장님 확인 대기)

토대로. 두 장점을 뽑아 최고의 프로젝트를 만들고 싶다. 먼저 어떤 장점을 뽑을 수 있는지 기획부터."

### Odoo 에서 이미 뽑은 것(유지) — 목적성·활용성
만들기 한 장(119) · 하나씩 켜기(118) · 칸반+다음 활동(121) · 연결 허브(122) · 상태 보고 신호등(114) ·
마일스톤 D-day · 돈 자동(115). **역할 분담: Odoo = 프로젝트의 '왜·어디까지·건강', monday = 태스크의
'빠른 입력과 한눈'.**

### 결합 결정안 (목업 4차로 확인 후 확정)

- **결정안 124 — 목록 보기 = monday 식 표 입력**: 목록을 '읽는 표'에서 **'입력하는 표'로 격상** —
  그룹(색)별 섹션, 맨 아래 인라인 ＋줄(치고 Enter → 다음 줄), 셀 클릭 즉시 편집, 숫자 컬럼은
  그룹·전체 합계 줄. 칸반과 같은 태스크의 두 얼굴(칸반=옮기는 손, 표=쌓는 손).
- **결정안 125 — 컬럼 추가 = 사용자 지정 속성**: 표 오른쪽 ＋ → 타입 선택(상태·사람·날짜·기간·숫자·
  글·선택지). 추가한 컬럼은 카드·서랍에도 자동으로 속성이 된다. 기존 project_boards 커스텀 칸의
  장점을 태스크 모델 위에 되살리는 것 — KPI 목표/실적 같은 숫자쌍도 이 길로.
- **결정안 126 — 상태(색 라벨)로 신호등 통합**: 결정 121의 신호등(보통/순조/막힘)을 monday 식
  **상태 컬럼**으로 흡수 — 라벨·색 커스텀 가능, 기본 팔레트는 사장님 실사용 5색. 단계(칸반 열)와
  상태(색 라벨)는 별개 축임을 명시(막힘은 어느 단계에서든 막힘).
- **결정안 127 — 그룹 축(선택 기능)**: ＋기능에 '그룹'을 추가 — 켜면 목록이 단계가 아니라 그룹
  (예: 팀원별 KPI / 사업 마일스톤)으로 묶인다. 칸반은 언제나 단계 축. 안 켜면 목록도 단계 묶음(단순 기본).
- 문장형 자동화(M8)는 결정 123이 이미 그 문법 — 레시피 문장 UI 로 그린다("상태가 막힘이 되면 →
  대표에게 알림"). 미션·이슈 보드의 CEO 지시↔보고 흐름은 별도 보드가 아니라 **그룹+표 입력으로
  프로젝트 하나("미션")를 만들면 되는 것**으로 갈음 — 메뉴를 늘리지 않는다.

### 4차 보강 — 사장님 계정으로 지정 보드 직접 확인 (2026-08-31, mo-tive-company 워크스페이스)

사장님이 본인 monday 계정을 열어 줘 지정 보드(5027666122 "홍보지원_소상공인 관리")와 워크스페이스
전 메뉴를 브라우저로 실사했다. 워크스페이스 보드 4개: 소상공인 관리(364개사) · 광고 성과 관리 ·
오프라인 교육 · (테스트 사본). **결정적 발견 — 이 보드들은 할 일 관리가 아니라 "운영 시트"다**:
아이템 하나 = 소상공인 한 곳(광고 ID·로그인 ID·비즈월렛·랜딩페이지·계약 날짜·마지막 소통일·
아드리엘 연동 같은 레코드 필드), 12.1억 정부사업의 실무 코어가 표 하나에 산다.

추가로 뽑은 장점:
| # | 장점 | 근거 |
|---|---|---|
| M10 | **아이템 용어 커스텀** — '아이템'이 아니라 "소상공인"이라 부른다. ＋버튼도 "새로운 소상공인" | item_terminology 실사용 |

  같은 태스크 모델 + 커스텀 컬럼(125)로 구현되며, 만들 때(119) "무엇의 목록인가요?"로 **부르는 이름**만
  정하면 된다(할 일/소상공인/거래처/…). ★기존 project_boards 의 커스텀 표가 사실 이 사용례였다 —
  버리는 게 아니라 태스크 모델 위에 다시 세우는 것.
- **결정안 129 — 저장된 보기 탭**: 필터·정렬·그룹화·컬럼 숨김 상태를 이름 붙여 탭으로 저장

  프로젝트 단위 공유 저장. ＋보기 카탈로그(118)와 한 줄에 산다.
