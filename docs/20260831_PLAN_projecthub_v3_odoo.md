## 1. History — 그리고 왜 '싹 무시'인가

지금 프로젝트 메뉴는 **표(템플릿) 중심**이다: 프로젝트 안에 '회의·결정', '할 일·진행', '매출 흐름' 같은
표를 여러 개 만들고, 각 표가 칸·그룹을 커스텀한다. 유연하지만 —
- 일 하나(태스크)가 1급 시민이 아니라 "표의 한 줄"이다. 체크리스트·하위 할 일·댓글·반복·앞뒤 순서
  같은 **일의 속성**이 표 구조에 눌려 자라지 못했다.
- 표마다 문법이 달라 "지금 뭘 해야 하나"가 프로젝트를 열어봐야 보인다. 전체 화면이 안내판이 아니라 목록이다.
- Odoo 가 파는 핵심 — "포스트잇처럼 붙이면 파이프라인이 정리된다"(칸반 우선), 마일스톤·예산·수익성이
  프로젝트 얼굴에 붙어 있는 것 — 이 구조적으로 안 나온다.
- (참고) 오늘 다른 PC 에서 기획 v2.6 '개편 1단계'가 배포 중(모티브 게이트) — 이 v3 기획은 그 방향까지
  포함해 **사장님이 고르는 상위 기획**이다. v3 채택 시 v2.6 은 흡수/중단을 그때 정한다.

## 2. 자문자답

① **무엇을 기준으로 판단되어야 하는가** — 화면의 단위는 표가 아니라 **할 일(태스크)** 이다. 프로젝트의
  건강은 사람이 남긴 **상태 보고(순항/주의/지연)** + 숫자(지연 건수·예산 소진·마일스톤 D-day)로 판단한다.
② **사용자는 왜 이 메뉴를 여는가** — (a) 내가 오늘 할 것 (b) 프로젝트들이 지금 괜찮은가 (c) 이 일의
  다음 단계. 세 질문이 각각 첫 화면이 된다: 내 할 일 · 전체(카드) · 칸반.
③ **반대 경우** — 표가 꼭 필요한 일(청구 회차, 광고 지표)은? → '목록 보기'가 표를 대체하고,
  돈 흐름은 현황 탭의 돈 패널(견적·계약·전표 자동 연동)로 옮긴다. 표 커스텀 칸이 필요한 경우를 위해
  사용자 지정 속성(칸 추가)은 남긴다 — 단 태스크의 속성으로.
④ **자동으로 못 푸는 것** — 상태 보고(순항/주의/지연)는 사람이 쓴다. 숫자는 옆에 자동으로 붙는다.
  수익성 숫자는 오너뷰가 자동으로 잇는다(견적→계약→계산서→수금, 지출 전표) — Odoo 는 타임시트로
  풀지만 우리는 장부가 이미 있다. **타임시트는 안 만든다**(직원들에게 시간 기록을 시키는 문화 비용 > 효익).

## 3. 결정 (109~117)

- **결정 109 — 단위 교체**: 표(project_boards) 중심 → **프로젝트 › 할 일(task)** 중심. 할 일은
  단계(stage)·담당(여럿)·마감·태그·우선순위·체크리스트·하위 할 일·첨부·댓글(기록)·반복·앞뒤 순서·
  마일스톤 연결을 **속성으로** 가진다. AS_IS 표의 줄 ▶ TO_BE 태스크 카드. 기존 데이터는 표별 이관
  스크립트(표 한 줄 → 태스크 하나, 그룹 → 단계)로 옮긴다 — 마이그레이션은 구현 단계에서 결정.
- **결정 110 — 첫 화면 = 전체 카드**: 프로젝트마다 카드 하나 — 상태 신호등(사람이 쓴 최신 상태 보고),
  진행률(완료/전체), 다음 마일스톤 D-day, 예산 게이지(지출 전표 합/예산), 담당 아바타, 지연 배지.
  카드가 안내판이다 — 눌러야 아는 화면 금지(건수 알림 드릴다운 규칙 준수).
- **결정 111 — 보기 5종**: 칸반(기본) · 목록 · 간트 · 캘린더 · 현황. 프로젝트 안 어느 보기든 같은
  태스크를 본다. Odoo 의 그래프/피벗은 '현황' 탭 하나로 합친다(전문용어·화면 수 최소화 — 사장님 취향).
- **결정 112 — 칸반이 입력이다**: 단계는 프로젝트마다 커스텀(+단계), 카드 빠른 추가(제목+Enter),
  끌어서 단계 이동. 카드에 보이는 것: 별(우선), 제목, 태그, 체크리스트 n/m, 하위 n, 댓글 n, 마감(지연 빨강),
  반복 ↻, 아바타. Odoo 칸반 문법 그대로, 이름은 순한국어.
- **결정 113 — 기록(채터) 통합**: 태스크마다 댓글+변경 로그가 한 줄기 타임라인. 팔로워가 알림 받는다.
  회의록 템플릿은 별도 화면 대신 "회의" 태그 + 기록으로 흡수(안건→결정→할 일 전환 버튼 유지).
- **결정 114 — 상태 보고(프로젝트 업데이트)**: 현황 탭 맨 위. 순항/주의/지연 + 한 줄. 전체 카드
  신호등의 유일한 출처. 안 쓰면 "보고 없음 n일" 로 회색 — 자동으로 색을 추측하지 않는다.
- **결정 115 — 돈 패널(오너뷰 강점)**: 현황 탭에 예산 vs 실제(견적·계약·계산서·수금·지출 전표 자동
  연결). Odoo 의 판매주문·청구서 발행 정책은 이미 있는 견적→계약→발행 흐름을 잇는 것으로 갈음.
- **결정 116 — 내 할 일**: 전 프로젝트 횡단 — 지연 / 오늘 / 이번 주 / 다음. 대시보드 위젯과 같은 원천.
- **결정 117 — 버린 것**: 타임시트·VoIP·고객 포털·평점 설문·이메일로 태스크 생성 —
  10인 회사 규모에 문화 비용이 효익보다 크다(벤치마킹은 덜어낸 버전으로 — 사장님 확정 취향).
  피벗/그래프 보기 분리, 커버 이미지, SMS 템플릿도 제외.

## 4. Odoo 기능 ↔ v3 대응표

| Odoo | v3 | 비고 |
|---|---|---|
| 칸반/목록/간트/캘린더 | 그대로 (보기 4종) | 기본=칸반 |
| 그래프·피벗 | '현황' 탭 하나로 | 번다운·단계별·담당별 |
| 하위 작업·반복·종속성·마일스톤 | 태스크 속성으로 그대로 | 종속성 이름은 '앞뒤 순서' |
| 채터(작업 로그)·팔로워 | '기록' 타임라인 | 댓글+변경 로그 통합 |
| 프로젝트 업데이트(상태 보고) | 그대로 — 신호등의 원천 | 사람이 쓴다 |
| 예산·수익성 | 돈 패널 — 장부 자동 연결 | 타임시트 없이 |
| 텍스트 단축키·일괄 처리·보관 | 빠른 추가·다중 선택 바·보관 | 기존 SelectionBar 문법 |
| 자동화 작업 | 규칙형 제안(확정은 사람) | 기존 자동화 원칙 |
| 타임시트·포털·평점·VoIP·이메일 수신 | **안 함** | 결정 117 |

## 5. 누락 점검·파급 (요약)

권한(/projecthub 키 유지, 내 담당만/전체 열람 그대로) · 기존 데이터(표→태스크 이관 — 구현 단계 별도 결정,
광고 표는 대시보드로 존치) · 빈 상태(프로젝트 0/할 일 0/보고 없음 각각) · 파급(대시보드 위젯·일정/할 일
연동·견적→계약 흐름·projecthub/[id] 전체) · 모바일(칸반 가로 스크롤). 구현은 **사장님이 목업을 보고
방향을 확정한 뒤** 단계 기획(마이그레이션 포함)을 따로 세운다 — 이 문서는 기획+목업까지다.
