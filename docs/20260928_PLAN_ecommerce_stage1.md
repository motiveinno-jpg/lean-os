## ② 자문자답
1. **무엇을 기준으로 판단하는가**
   - 클레임의 기준 단위는 **주문번호 1건**(channel_order_imports 행). 부분 반품은 환불 금액을 사람이 고치고, 재고는 그 주문의 줄(stock_moves 중 note 가 "채널 주문번호" 인 줄) 전부 또는 사람이 고른 줄만 되돌린다.
   - 재고 되돌림은 **반품 입고(return_in) 문서**로 남긴다(판매 출고를 지우지 않는다 — 지우면 이력이 사라지고 원가 층이 흔들린다). 교환은 반품 입고 + 교환 출고(sale, 금액 0) 두 문서.
   - 정산의 기준 단위는 **정산 내역 한 줄**(채널이 준 주문번호·정산일·정산금·수수료). 주문과의 대조 키는 (채널, 주문번호). 같은 줄 두 번 붙여넣기는 (회사·채널·주문번호·정산일·정산금) 유일 제약으로 막는다(결정 17 과 같은 결).
   - 실측 수수료율 = Σ수수료 ÷ Σ판매금액(채널별). 설정값(channel_fees.fee_rate)과 차이가 1%p 넘으면 화면이 **제안**하고 사람이 갱신을 누른다.
2. **사용자는 왜 하는가** — ① 취소·반품이 KPI 와 재고에 반영 안 되면 매출·재고가 둘 다 부풀린다 ② 채널 정산금은 수수료·배송비·광고비가 빠져 들어와 "얼마 받았는지" 를 주문과 대조하지 않으면 미정산·과다 공제를 못 본다 ③ 정산 입금이 통장에 뭉텅이로 들어와 전표를 손으로 쪼개고 있다.
3. **반대 경우**
   - 출고 전 취소 → 재고 되돌림 기본 ON(출고 문서가 이미 있으므로 반품 입고로 상계). 배송 완료 후 반품 → 되돌림 기본 ON, 파손 반품이면 사람이 OFF 하고 폐기는 창고관리에서.
   - 같은 주문에 두 번째 클레임(부분 반품 두 번) → 허용, 환불 합계가 주문 금액을 넘으면 경고만.
   - 정산 내역에 주문 기록이 없는 줄(엑셀로 안 가져온 주문·광고비·보정) → "주문 없음" 으로 남기고 합계에는 넣는다. 음수 정산(환불 차감) → 허용.
   - 채널 정산 엑셀 열 이름은 채널·시기마다 다르다 → 열 매핑은 사람이 한 번 고르고 저장(택배사 시트 양식과 같은 방식).
4. **자동으로 못 푸는 것** — 실키 없는 자동 수집·발송 통보(2단계) · 부분 반품의 품목 판별(사람이 줄을 고른다) · 정산 전표의 계정(회사마다 다르다 → 초안 팝업에서 계정 고르고 기억) · 채널 재고 수량 반영(키 필요).

## ④ 누락 점검
- 권한: `/inventory/channels`(보기) · `:write`(클레임 등록·정산 붙여넣기·수수료율 갱신·전표 초안). 새 메뉴 키 없음 → 백필 불필요.
- RLS: 두 새 표 모두 회사 격리(company_id = 내 회사, 기존 채널 표와 같은 정책 문법). db-architect 가 마이그레이션.
- 빈 상태: 클레임 0 → "취소·반품이 없습니다"; 정산 0 → 붙여넣기 안내.
- 경계값: 환불액 0·음수 금지 / 정산금 음수 허용 / 부분 반품 합계 > 주문 금액 경고 / 주문 없음 줄 / 같은 줄 재붙여넣기 유일 제약.
- 중복 실행: 클레임 저장 = 표 1행 + 문서(트랜잭션 아님) → 문서 만든 뒤 행 insert 실패 시 문서 삭제(importChannelDoc 과 같은 되돌림).
- 되돌리기: 클레임 삭제 시 되돌림 문서도 삭제(문서가 다른 전표에 묶였으면 막음). 정산 batch 삭제 가능(전표 초안 생성 뒤엔 막음).
- 파급 화면: SalesBoard 채널 축 · 이커머스 현황 · 재고 현황(채널 비중은 문서 기준이라 그대로) · 이익관리(반품 입고가 원가 층에 들어감 — 기존 return_in 처리 그대로).
- 외부 전송·인쇄·마감·모바일: 해당없음(표 가로 스크롤 한 겹).
