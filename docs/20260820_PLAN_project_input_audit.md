# 프로젝트 템플릿 입력 화면 전수 점검 — 진단 + 개선 기획 (2026-08-20)

목적에 따라 입력이 잘 되는지 전체적인 점검 — 문제점 진단 + 개선 목업 기획 추천."

## ① History — 왜 지금 이 모양인가

- 2026-08-07 사장님: "템플릿이 다 똑같은 표라 실제 업무에 의미가 있는지 모르겠다"
  → `inputModesOf()` 로 템플릿마다 **그 일 전용 첫 화면**을 맨 앞에 세웠다
  (회의록·지출 입력·건별·접수함·캘린더·만기). 표·칸반은 뒤에 남긴다.
- 그래서 "표만 있다" 문제는 이미 풀려 있다. 이번 점검은 그 전용 화면 **안에서**
  적다가 끊기는 지점을 찾는 일이었다.

## ② 점검 방법

시연 프로젝트(A커머스 브랜드몰 구축)의 8개 탭을 Playwright 로 전수 캡처
(.playwright-mcp/pin-*.png) + BoardMinutes/Expense/Deals/Inbox/Calendar/Expiry/
QuickAddRow 코드 대조.

| 템플릿 | 첫 화면 | 판정 |
|---|---|---|
| 회의 · 결정 | 회의록 | ⚠ 구멍 ① |
| 예산 · 지출 | 지출 입력 | ⚠ 구멍 ② |
| 계약 · 갱신 | 만기 | ⚠ 구멍 ③ |
| 할 일 · 진행 / 마케팅 / 직접 | 표 + 빠른 줄 | ⚠ 구멍 ④ |
| 매출 흐름 | 건별 | ✅ (파이프라인·문서 체인·청구 줄 제안) |
| 요청 · 검수 | 접수함 | ✅ (내게 온/내가 낸/끝난 + 폼) |
| 일정 · 마일스톤 | 캘린더 | ✅ (드래그로 기간, 이름만 적으면 끝) |
| 보기 기억 | — | ✅ 나갔다 오면 기본 첫 화면(표준과 동일 원칙) |

## ③ 자문자답

1. **무엇을 기준으로 판단하나** — "그 템플릿의 목적 동작(적기·챙기기)이 첫 화면 하나에서
   끝나는가, 적은 데이터가 요약·정렬에 바로 잡히는가."
2. **사용자는 왜 적는가** — 기록 자체가 아니라 다음 행동(만기 챙기기, 예산 남은 돈,
   할 일 배분)을 위해서다. 적는 순간 그 행동 축(날짜·단계)이 비면 적으나 마나다.
3. **반대 경우** — 기본값이 싫은 사람: 단계·날짜 모두 그 자리에서 바꾸거나 비울 수 있게
   남긴다(강제 아님).
4. **자동으로 못 푸는 것** — 이미 생긴 중복 할 일(어느 줄이 진짜인지), 날짜 없는 지난
   지출(언제 썼는지)은 사람만 안다 → 지우지 않고 화면에 그대로 두고 사람이 정리.

## ④ 결정 (사장님 확정 대기)

**결정 1 — [회의] '할 일로 보내기'는 한 번만**
- 규칙: 성공 시 안건 values 에 만든 할 일 id 기록(`__todo_item`), 버튼 → "할 일로 보냄 ✓".
  다시 누르면 새 줄 대신 그 할 일을 연다.
- AS_IS ▶ TO_BE: 누를 때마다 insert(시연 데이터에 같은 이름 3줄 실증) ▶ 1안건=1할 일.
- 적용: 즉시. 기존 중복 줄은 삭제하지 않음(진짜 판별은 사람).

**결정 2 — [지출] 빠른 입력 줄에 결제일(기본 오늘)**
- 규칙: BoardExpense 입력 줄에 날짜 칸 추가, 기본 오늘, submit 시 date 칸에 기록.
- AS_IS ▶ TO_BE: 날짜 없이 저장 → '최근'(결제일 순)·주별 추이에서 빠짐 ▶ 적는 즉시 잡힘.
- 적용: 즉시. 날짜 없는 지난 줄은 그대로(줄 열어 채움).

**결정 3 — [계약] 만기 화면에서 바로 적는다**
- 규칙: BoardExpiry 상단에 ＋ 계약 적기 한 줄(계약명·거래처·금액·시작·만기),
  만기 미입력 카드엔 "표에서 채워 주세요" 대신 날짜 입력을 그 자리에.
- AS_IS ▶ TO_BE: 만기 화면 읽기 전용, 입력은 표로 이동 ▶ 적기·챙기기가 한 화면.
- 적용: 즉시. 기존 데이터 처리 해당없음.

**결정 4 — [표 공통] 빠른 입력 줄의 흐름 칸은 첫 단계 기본**
- 규칙: QuickAddRow 열릴 때 status(flow) 칸 첫 옵션 미리 선택(바꾸기·비우기 가능).
  sendToTodo 가 이미 쓰는 "첫 단계에 세운다"와 정책 통일.
- AS_IS ▶ TO_BE: 단계 빈 줄 → 칸반 '단계 미지정' ▶ 새 줄은 첫 단계에서 출발.
- 적용: 새로 적는 줄부터. 기존 빈 줄 안 건드림('단계 미지정' 묶음이 계속 보여 줌).
- 누가 정하는 값: 기본값(첫 단계) < 사용자가 그 줄에서 고른 값. 회사설정 없음.

### 버린 안
- **템플릿별 전용 입력 화면 신설** — 이미 6/8 존재, 새로 만들 것 없음(8/7 에 끝난 일).
- **중복 할 일 자동 병합/삭제** — 어느 줄이 진짜인지 시스템이 모른다.
- **표 기본 → 칸반 기본 전환(할 일)** — 표+빠른 줄이 이미 표준이고 문제는 기본값 부재.
- **지출 날짜 필수화** — 몰아 적기 흐름을 막는다. 기본 오늘이면 충분.

## ⑤ 누락 점검 (PLANNING_METHOD ④)

권한·RLS 해당없음(기존 표·기존 insert 경로 그대로) · 빈상태 유지(만기 화면 빈 문구는
입력 줄과 공존) · 경계값: 결정4 는 options 0개면 기본값 없이 지금처럼 · 중복실행:
결정1 이 바로 그 방지책, sendingTodo 가드 유지 · 마감/기존데이터: 각 결정에 명기 ·
외부전송·인쇄엑셀·모바일폭·되돌리기 해당없음(행 삭제 undo 기존 그대로).

## ⑥ 파급 화면

- `__todo_item` 값 키: BoardSummary·표·칸반은 values 의 모르는 키를 무시 — 파급 없음.
- 지출 날짜: BoardSummary(주별 추이)·pbe-list 정렬이 **좋아지는 쪽** 파급.
- 결정4: 칸반 '단계 미지정' 묶음이 줄어드는 쪽 파급.

구현 대상 파일: ProjectBoards.tsx(sendToTodo·QuickAddRow), BoardMinutes.tsx(버튼 상태),
BoardExpense.tsx(날짜 칸), BoardExpiry.tsx(입력 줄·인라인 날짜).
