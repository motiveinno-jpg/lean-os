# 회사 설정 개편 + API 키 관리 — 기획서 (2026-08-21)

> 사장님 지시: "회사메뉴에 이제 관리해야 하거나 연결해야 할 API키들이 많을 것 같은데
> API를 관리하는 메뉴를 만들거나 회사설정의 탭을 신설하는 게 좋을 것 같아.
> 지금 회사 부분이 따로 생겼는데 여기 메뉴를 한번 목적에 맞게 개편하는 게 어때?
> 탭에 들어가있는 것들도 회사 기초정보, 회계 등등 기획해볼래?"

작성 방법: `docs/PLANNING_METHOD.md` (History → 자문자답 → 결정 → 누락 점검 → 파급).

## ① History — 지금 왜 이 모양인가

### 자격증명이 **네 곳**에 흩어져 있다 (실측)

| 어디 | 무엇이 들어 있나 | 앱 화면에서 보이나 |
|---|---|---|
| `company_settings` 컬럼 | `codef_client_id` · `codef_client_secret` · `codef_connected_id` · `hometax_user_id` · **`hometax_password`** · `slack_webhook_url` | 일부만 (은행연동 탭) |
| `company_integrations` | `login_id` · `login_pw_encrypted` · `cert_dn` | 은행연동 탭 |
| `automation_credentials` | `service` + `credentials`(jsonb) | 광고 계정 탭 |
| **Supabase Edge 시크릿** | `DATA_GO_KR_API_KEY` · `ANTHROPIC_API_KEY` · `RESEND_API_KEY` · `KAKAO_*` · `CODEF_*` · `CRON_SECRET` 등 20여 개 | **전혀 안 보임** |

- **"무엇이 연결돼 있고 무엇이 끊겼는지" 한눈에 보는 곳이 없다.** 은행·광고 두 탭이 각각 자기 것만 보여준다.
- 네 번째 칸(Edge 시크릿)은 **Supabase 대시보드에서만** 넣을 수 있다.
  → 2026-08-21 실제로 여기서 막혔다. K-Startup 인증키를 받아 놓고도 넣을 방법이 없어 **수집 기능이 멈춰 있다.**
- `company_settings.hometax_password` 는 **평문 컬럼**이다(옆 테이블은 `login_pw_encrypted` 로 암호화하는데).

### 설정 탭은 10개 / 그룹 5개인데, 묶음이 성격을 못 따라간다

| 지금 그룹 | 지금 탭 | 무엇이 어긋났나 |
|---|---|---|
| 회사 | 회사정보 · 구성원·초대 | **회사정보가 잡화점** — 설명이 "사업자 정보와 직인·로고, 회사 문서, 세무 파트너 연결" 이다. 성격이 다른 네 가지가 한 탭에 있다 |
| 회계·자금 | 자금·통장 · 계정과목·분류 · 회계마감 | 여기는 맞다 |
| 연동 | 은행연동 · 광고 계정 | 실제 연동은 홈택스·슬랙·카카오·결제까지 있는데 **둘만 있다** |
| 근무·문서 | 근태·가산수당 · 회사 양식 | **억지 묶음** — 출퇴근 기준과 PDF 양식은 아무 관계가 없다 |
| 시스템 | 회사 삭제 | 맞다 |

그리고 어제 만든 **지원사업 회사 카드 7문항**(개업일·업종·규모·인증·수출)이 지원사업 화면 안에만 있다.
이건 성격상 **회사 기초정보**다 — 다른 기능도 쓸 값인데 한 화면에 갇혀 있다.

## ② 자문자답

**Q1. 무엇을 기준으로 탭을 나누는가?**
화면 개수나 기능 이름이 아니라 **"무엇을 정하는 곳인가"** 로 나눈다. 사용자가 설정에 오는 이유는
언제나 "○○를 바꾸려고" 이고, 그 ○○는 대개 이 일곱 가지 중 하나다 —
우리 회사가 무엇인가 / 누가 쓰는가 / 장부를 어떻게 다루나 / 일하는 기준 / 바깥과 어떻게 연결되나 /
내보내는 종이 / 위험한 것.

**Q2. 사용자는 API 키 화면에 왜 오는가?**
키를 **넣으러** 오는 게 아니라 **"왜 안 되지?"** 를 확인하러 온다.
그래서 화면의 주인공은 입력칸이 아니라 **연결 상태**여야 한다 — 연결됨 / 키 없음 / 실패(사유).

**Q3. 반대 경우(예외)는?**
- ㉠ **회사 키와 플랫폼 키는 성격이 다르다.** 광고 계정·은행 인증서는 이 회사 것이고,
  K-Startup·기업마당·Claude 키는 **오너뷰 전체가 쓰는 하나**다. 한 화면에 섞으면
  회사 대표가 플랫폼 키를 지울 수 있게 된다. → **층을 가른다**(플랫폼 키는 마스터 전용).
- ㉡ **키를 넣었는데 틀린 키인 경우.** 오늘 실제로 그랬다 — 기존 `DATA_GO_KR_API_KEY` 는
  다른 계정 키여서 K-Startup 에 등록돼 있지 않았고, 호출해 보기 전까지 아무도 몰랐다.
  → **저장 즉시 실제로 한 번 호출**해 본다(연결 테스트).

**Q4. 자동으로 못 푸는 것은?**
- **키 자체는 사람이 발급받아 온다.** 우리가 대신 받을 수 없다.
  → 각 연동마다 **어디서 어떻게 받는지**를 화면에 적는다(오늘 사장님이 "기업마당 키 어떤 걸 받아야 하는지
  모르겠다"고 하신 것이 바로 이 구멍이다).
- **평문으로 다시 보여줄 수 없다.** 암호화해 저장하면 우리도 못 읽는다.
  → 마스킹(`5530…Ds`)만 보여주고, 바꾸려면 다시 넣는다.

## ③ 결정

### 결정 1. 키는 **DB에 암호화해서 넣는다** — Supabase 대시보드를 벗어난다

- **규칙** — 새 표 `platform_credentials`(플랫폼 키). 값은 기존 `encrypt_credential()` pgcrypto RPC로 암호화한다.
  키는 `vault.decrypted_secrets` 의 `credential_encryption_key` 이고 **DB 밖으로 나가지 않는다**.
  엣지 함수는 service_role 로 `decrypt_credential()` 을 불러 쓴다(이미 codef-sync 가 쓰는 방식).
- **AS_IS ▶ TO_BE** — Edge 시크릿(대시보드에서만 입력) ▶ 앱 화면에서 마스터가 입력·교체·삭제.
  엣지 함수는 **시크릿 먼저, 없으면 DB** 순으로 읽는다 → 기존 키를 안 건드리고 점진 이전.
- **적용 시점** — Phase 1.
- **기존 데이터** — 손대지 않는다. 시크릿에 이미 있는 키는 그대로 동작한다.
- **버린 안**: 회사 키 표(`automation_credentials`)에 플랫폼 키를 같이 넣는 안.
  그 표는 `company_id` 가 필수이고 RLS 가 회사 단위다 — 플랫폼 키를 넣으면
  **어느 한 회사 소유가 되고 그 회사 대표가 읽을 수 있다.** 성격이 다른 것을 한 표에 담으면 안 된다.

### 결정 2. 화면의 주인공은 입력칸이 아니라 **연결 상태**

- **규칙** — `회사 설정 › 연동·API 키` 첫 화면은 **연결 카드 목록**이다.
  각 줄: `[아이콘] 이름 · 상태칩(연결됨/키 없음/실패) · 마지막 사용 · 키 마스킹 · [연결 테스트] [관리]`
- 실패한 줄에는 **사유를 그대로 적는다** (`등록되지 않은 서비스키` 처럼 기관이 준 문구 그대로).
- **버린 안**: 탭마다 입력칸만 두는 지금 방식. "넣었는데 왜 안 되지"를 화면이 답해 주지 못한다.

### 결정 3. **저장하면 즉시 한 번 호출해 본다** (연결 테스트)

- **규칙** — 키를 저장할 때 그 API 를 실제로 1회 호출하고 결과를 그 자리에서 보여준다.
  성공하면 `연결됨`, 실패하면 기관이 준 오류 문구를 그대로.
- **왜** — 2026-08-21 실증: 기존 data.go.kr 키가 K-Startup 에 미등록이라
  `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 났는데, 함수를 배포하고 호출해 보기 전까지 몰랐다.
  **테스트가 없으면 이 시간이 매번 반복된다.**

### 결정 4. **키를 어디서 받는지 화면에 적는다**

- **규칙** — 연동마다 `발급처 · 발급 링크 · 신청 시 넣을 값 · 주의사항`을 접이식으로 담는다.
  예) 기업마당 — bizinfo.go.kr 활용신청 · 로그인 불필요 · 즉시 발급 ·
  **시스템IP 대신 URL(`https://www.owner-view.com`)을 고를 것**(서버 IP가 고정이 아니다).
- **왜** — 사장님이 "기업마당 인증키 어떤 걸 받아야 하는지 모르겠어"라고 하신 그 구멍을 화면이 메운다.
  이건 우리 회사만의 문제가 아니라 **오너뷰를 쓰는 모든 회사가 똑같이 겪는다.**

### 결정 5. 설정 탭을 **7그룹**으로 재편 — "무엇을 정하는 곳인가"로

| # | 그룹 | 탭 | 무엇을 정하나 |
|---|---|---|---|
| 1 | **회사 기초정보** | 사업자 정보 · **회사 카드**(지원사업 7문항 흡수) · 직인·로고 | 우리 회사가 무엇인가 |
| 2 | **구성원** | 구성원·초대 · 부서 | 누가 쓰는가 |
| 3 | **회계·세무** | 계정과목·분류 · 회계마감 · 자금·통장 · **세무 파트너**(회사정보에서 분리) | 장부를 어떻게 다루나 |
| 4 | **근무 규칙** | 근태·가산수당 | 일하는 기준 |
| 5 | **연동·API 키** ★신설 | **연결 현황** · 은행·카드(CODEF) · 홈택스 · 광고 계정 · 알림(Slack·카카오) · **플랫폼 키**(마스터) | 바깥과 무엇으로 연결되나 |
| 6 | **문서·양식** | 회사 양식 | 회사가 내보내는 종이 |
| 7 | **시스템** | 회사 삭제 | 위험한 것 |

- **AS_IS ▶ TO_BE**
  - `회사정보`(잡화점) ▶ `사업자 정보` + `회사 카드` + `세무 파트너`(회계·세무로) 로 쪼갠다.
  - `연동`(은행·광고) ▶ `연동·API 키`(연결 현황이 첫 화면, 그 아래 개별 연동).
  - `근무·문서`(억지 묶음) ▶ `근무 규칙` / `문서·양식` 으로 가른다.
- **적용 시점** — Phase 2.
- **기존 데이터** — 화면 재배치일 뿐 데이터는 그대로.
- **⚠️ 권한 키를 깨뜨리지 않는다** — `SETTINGS_TABS[].perms` 는 이미 부여된 옛 키를 OR 로 받아 준다.
  탭을 쪼갤 때 **새 키를 만들지 말고 기존 키를 그대로 물려준다**(`company-info` → 새 두 탭이 같이 씀).
  안 그러면 지금 권한을 가진 사람이 내일 못 본다.

### 결정 6. 평문 자격증명 컬럼은 **점진 이전**

- **규칙** — `company_settings.hometax_password` 등 평문 컬럼을 암호화 저장으로 옮긴다.
  읽는 쪽은 "암호문이면 복호화, 평문이면 그대로" 로 두 형태를 다 받는다 → 한 번에 안 깨진다.
- **적용 시점** — Phase 3. 급하지 않지만 **보안 부채로 남겨 두지 않는다.**

## ④ 누락 점검

| 항목 | 처리 |
|---|---|
| 권한 | 회사 키 = owner·admin / **플랫폼 키 = 마스터 전용**(`masterOnly`). 기존 `perms` 키 승계 |
| RLS | `platform_credentials` — 회사에 속하지 않는다. SELECT/쓰기 모두 **마스터만**(users.is_master), 값 컬럼은 암호문 |
| 역할 | 직원·세무사에게는 연동 탭 자체가 안 보인다 |
| 빈 상태 | 키가 하나도 없으면 "무엇을 연결하면 무엇이 되는지" 목록으로 안내 |
| 경계값 | 키 문자열 공백·줄바꿈 트림(과거 `\n` 이 붙어 realtime 이 깨진 사례 있음), Encoding/Decoding 키 양쪽 허용 |
| 중복 실행 | 연결 테스트 연타 방지(진행 중 비활성) |
| 마감 | 해당 없음 |
| 기존 데이터 | 시크릿 우선 → DB 폴백. 기존 동작 무변화 |
| 파급 화면 | `settings/page.tsx`(탭·그룹) · `lib/permissions.ts` · 지원사업(회사 카드 이전) · 엣지 함수(키 읽는 순서) |
| 외부 전송 | 연결 테스트는 **해당 기관에만** 호출. 키를 다른 곳으로 보내지 않는다 |
| 인쇄·엑셀 | 해당 없음 |
| 모바일 폭 | 연결 카드는 1열로 |
| 되돌리기 | 키 교체 시 이전 값은 복구 불가(암호화) — **교체 전 확인 팝업** |
| 감사 | 키 등록·교체·삭제는 `audit_logs` 에 남긴다(값은 절대 안 남긴다) |

## ⑥ 사장님 확정 (2026-08-21) — 기획 ③·⑤가 바뀌었다

1. **5그룹으로 줄인다** — 근무 규칙은 `구성원` 에, 문서·양식은 `회사 기초정보` 에 흡수.
   → 회사 기초정보 / 구성원 / 회계·세무 / **연동·API 키** / 시스템.
2. **플랫폼 공용 키가 아니라 회사별 키다.** (결정 1을 뒤집는다)
   > "플랫폼키는 회사별로 입력 안 하면 쓰지 못하게. 현재 오너뷰에 내가 등록한 건은 모티브이노베이션
   >  전용 플랫폼키야. 회사가 자기 키를 넣었을 때만 쓸 수 있게. 넣지 않았을 때는 발급받을 수 있는
   >  사이트로 바로가기 기능 제공"
   - `platform_credentials`(마스터 전용) 안을 버리고 **`company_api_keys`(회사별, RLS 회사 단위)** 로 간다.
   - **왜 이게 맞나** — 공공데이터포털·기업마당 키는 발급받은 계정의 **호출 한도**를 쓴다.
     우리 키 하나로 전 회사를 돌리면 회사가 늘수록 한도가 먼저 터지고 그 순간 **전 회사가 동시에 멈춘다.**
   - 상시 제도(고용장려금·세액공제)는 API 가 필요 없으므로 **키 없이도 그대로 보인다.**
     공고 자리에만 발급 안내가 뜬다 → 맛보기(금액 계산)는 무료, 공고 수천 건은 키를 넣어야.
3. **회사 카드는 지원사업 화면에 그대로 둔다** — 옮기지 않는다.

## ⑦ 만든 결과 (Phase 1 완료)

- `company_api_keys` — 회사별·암호화·연결 상태. RLS 는 회사 + owner·admin.
- `회사 설정 › 연동·API 키` — 연결 현황 · 발급 안내(단계·주의사항) · **저장 전 실제 호출 확인** · 연결 테스트 · 지우기.
- `POST /api/integrations/test-key` — **사용자 세션 그대로** 쓴다(service_role 안 씀).
  그래야 `company_api_keys` RLS 가 "자기 회사 것만" 을 DB 에서 강제한다.
- `gov-programs-sync` — 회사가 등록한 키로 K-Startup·기업마당을 받아 공용 카탈로그에 upsert.
  한 곳도 성공 못 한 원천은 **아무것도 닫지 않는다**(키가 막힌 날 목록이 통째로 사라지면 안 된다).
- 지원사업 화면 — 키 없는 원천의 공고는 안 보이고, 위에 발급 안내 띠가 뜬다.
