# 세무 모듈 기획 — 원천세 · 법인세 · 부가세 · 지급명세서 (2026-08-31)

사장님 지시: "오너뷰를 통해 세금 신고를 할 수 있는지, 안 되면 개선 기획. 원천징수·법인세 등 ERP 세무 항목."

---

## 0. 먼저 답부터 — "오너뷰에서 신고가 되는가?"

**지금은 안 되고, 앞으로도 '제출 버튼'은 만들 수 없다. 그러나 그 직전까지는 전부 만들 수 있다.**

국세청은 세무 신고 API를 외부에 열지 않는다. 법인이 신고하는 길은 세 가지뿐이다:
1. **홈택스 화면에 직접 입력** — 지금 우리 부가세 '신고서 준비'가 돕는 방식(옮겨 적기).
2. **홈택스 '신고서 파일 변환' 업로드** — ERP가 국세청 전자신고 파일 포맷(원천세 위한 지급명세서 파일 등)으로
   만들어 주면 사람이 업로드. 이카운트·더존도 여기까지다. **어떤 ERP도 "ERP 안에서 제출 완료"는 못 한다.**
3. **세무대리인(세무사)** — 소기업 대부분의 현실. ERP의 역할은 세무사에게 줄 자료 패키지.

→ 그래서 목표를 "제출"이 아니라 **"옮겨 적기 0"**으로 정한다: 신고서를 국세청 서식 칸 그대로 완성하고,
기한을 관리하고, (마지막 단계로) 전자신고 파일까지. 제출만 홈택스에서 사람이 누른다 —
기존 결정 64(부가세: "신고는 홈택스에서 사람이")의 확장이다.

## 2. 자문자답

**① 무엇을 기준으로 판단되어야 하는가?**
신고서 숫자는 **확정된 것만**으로 만든다 — 부가세가 이미 그렇다(확정 매입매출전표만, 결정 60).
- 원천세: **발송/확정된 급여 배치의 payroll_items 스냅샷** (초안·미리보기는 제외 — 신고서가 흔들리면 안 된다)
- 법인세: **마감 확정본**(closing-snapshot) 손익 + 고정자산 감가상각. 마감 안 한 달이 있으면 그렇다고 적는다.

**② 사용자는 이걸 왜 하는가?**
매월 10일(원천세), 분기 25일(부가세), 3월 말(법인세)마다 같은 숫자를 홈택스나 세무사 메일에
**다시 입력**한다. 오너뷰에 이미 있는 숫자다. 이중 입력 = 시간 + 오타 리스크.

**③ 반대 경우가 있는가? (예외 설계)**
- **세무사에게 맡기는 회사**(소기업 대부분): 신고서 화면이 '제출용'이 아니라 **'검토·전달 패키지'**로도
  서야 한다 → 모든 신고서에 '세무사 전달 엑셀' 버튼(부가세와 같은 문법).
- **원천징수 대상 지급이 없는 달**: 인원 0·세액 0 이어도 원천세는 **무실적 신고** 대상이다 — "낼 것 없음"이
  아니라 "0으로 신고"라고 화면에 적는다.
- **환급(음수)**: 부가세 환급, 연말정산 환급 — 음수를 빨간 마이너스가 아니라 '환급'으로 읽어 준다.

**④ 자동으로 못 푸는 경우는? (사람에게 맡기고 화면에 적는다)**
- **제출** — 홈택스에서 사람이. 모든 신고서 화면 상단에 명시(결정 64 문구 재사용).
- **법인세 세무조정** — 접대비 한도·감가상각 한도·이월결손금 공제는 판단의 영역. 오너뷰는
  "회계이익 기준 근사치"라고 크게 적고, 확정은 세무사가 한다.
- **간이세액표·요율 연도 갱신** — 매년 2~3월 국세청 고시. 코드 상수라 배포로 갱신 — 화면에
  "2025 간이세액표 기준"처럼 기준 연도를 적어 어긋남이 보이게 한다.

## 3. 결정 (100~107)

### 결정 100 — 범위 선긋기: '옮겨 적기 0'까지, 제출은 사람
- **규칙**: 오너뷰 세무는 ①신고서 서식 그대로 완성 ②세무사 전달 엑셀 ③기한 관리 ④(마지막) 전자신고 파일까지.
  제출 버튼은 만들지 않는다(국세청 API 부재 — 어떤 ERP도 못 한다).
- **AS_IS**: 부가세만 ①② ▶ **TO_BE**: 원천세·법인세·지급명세서로 같은 문법 확장.
- **적용 시점**: 단계별(아래 로드맵). **기존 데이터**: 소급 조회 가능(급여 스냅샷·확정 전표가 이미 있다).

### 결정 101 — 1차: 원천징수이행상황신고서 (가장 급하고 재료가 다 있다)
- **규칙**: 매월 신고서 = 그 달 **발송/확정 급여 배치**의 payroll_items 합계.
  칸 대응: A01 근로소득(간이세액) — 인원·총지급액·소득세 / A99 합계 / 지방소득세는 참고 표기(지자체 신고).
  귀속월·지급월을 구분해 표기(지연 지급 대비). 무실적 달은 "0원 신고 대상"으로 표시.
- **AS_IS**: 급여는 공제 계산·명세서까지만 ▶ **TO_BE**: 신고서 칸 완성 + 엑셀 + 세금 일정(매월 10일)에서 바로 진입.
- **적용 시점**: 1차 배포 즉시. **기존 데이터**: payroll_items 있는 달은 소급 생성, 없는 옛 달은 "급여 발송 기록 없음".

### 결정 102 — 2차: 사업소득(프리랜서 3.3%) 지급
- **규칙**: 급여 배치에 **'사업소득자' 줄 유형** 추가(가장 좁은 변경 — 새 모듈을 만들지 않는다).
  소득세 3% + 지방소득세 0.3% 자동 공제, 신고서 A25 칸으로 집계.
- **AS_IS**: freelance 고용형태는 있는데 지급·원천징수 기록이 없다 ▶ **TO_BE**: 지급이 기록되고 신고서에 잡힌다.
- **기존 데이터**: 과거 프리랜서 지급(통장 이체)은 소급하지 않는다 — 앞으로 기록분부터.

### 결정 103 — 2차: 간이지급명세서 (근로 매월 · 사업소득 매월)
- **규칙**: 신고서와 같은 데이터로 인별 명세 엑셀 생성. 국세청 **전자제출 파일 포맷은 4차**로 미룬다
  (포맷 검증 실패 = 가산세 리스크, 엑셀로 먼저 검증).
- **기한**: 근로 간이지급명세서 반기(1·7월 말) / 사업소득 매월 말 — 세금 일정에 추가.

### 결정 104 — 3차: 법인세 '예상'과 세무사 패키지 (신고서는 안 만든다)
- **규칙**: 마감 확정 손익 → 회계이익 → 세율 구간(9/19/21/24%) → **예상 법인세 + 중간예납 예상**.
  화면에 "세무조정 전 근사치 — 확정은 세무사"를 크게. **신고서(별지 서식) 작성은 범위 밖** —
  세무조정(접대비·감가상각 한도·이월결손금)은 자동으로 풀 수 없는 판단이다(자문자답 ④).
- 대신 **'세무사 전달 패키지' 한 버튼**: 재무상태표·손익계산서·계정별 원장·고정자산 감가상각 명세 엑셀 묶음.
- **AS_IS**: 법인세 0 ▶ **TO_BE**: 3월에 세무사에게 보낼 것이 버튼 하나. 예상세액은 자금 전망(cash-outlook)에도 물린다.

### 결정 105 — 1차: 세금 일정 확장 (기존 tax_deadline_checks 재사용)
- 추가: 법인세 신고·납부(3/31), 법인지방소득세(4/30), 중간예납(8/31), 간이지급명세서 기한,
  연말정산 일정(간소화 오픈 1/15 · 환급 반영). 12월 결산 법인 기준 — 사업연도 설정은 회사설정에 두되 기본 12월.
- **AS_IS**: 부가세·원천세·4대보험만 ▶ **TO_BE**: 법인이 1년에 만나는 세무 기한 전부. 납부 완료 체크 그대로.

### 결정 106 — 4차(베타): 전자신고 파일 생성
- 원천세 지급명세서·부가세 전자신고 파일(홈택스 '변환 신고' 업로드용). **세무사 검토 전제 베타**로 게이트
  (feature_rollout — 모티브 먼저). 포맷 오류 = 신고 오류라 마지막에, 실제 신고 1회 검증 후 연다.

### 결정 107 — 메뉴 위치 (사장님 확인 필요)
- **제안**: 재무 그룹에 **'세무 신고'** 메뉴 신설 — 신고는 '분석'이 아니라 매월 하는 '업무'다.
  안: [원천세] [부가세] [법인세] [지급명세서] 갈래 탭. 분석 › 부가세의 '신고서 준비' 탭은 이쪽으로 옮기고
  분석에는 집계·예상만 남긴다.
- **버린 안**: 분석 › 부가세를 '세무'로 확장 — 원천세는 급여(인사) 데이터라 '분석 › 부가세' 이름 아래 두면 못 찾는다.
- ⚠️ 메뉴 신설/이동이므로 **PERMISSION_CATALOG·route-labels·NAV_ITEM_COLOR 동기 + member_permissions 백필** 필수.

## 4. 누락 점검 (PLANNING_METHOD ④)

- **권한/RLS**: 새 메뉴 → 권한 카탈로그 + **기존 회사 백필**(안 하면 마스터 외 안 보임 — 재발 사고).
  새 테이블(사업소득 지급 등)은 RLS 필수. 급여 데이터라 재무·인사 권한 교차 검토(security-reviewer, L 티어).
- **역할**: 원천세 신고서는 급여 총액이 보인다 — 급여 권한과 같은 등급으로.
- **빈 상태**: 급여 발송 없는 달·마감 없는 해 — "자료 없음"이 아니라 "무엇을 하면 생기는지" 적기.
- **경계값**: 환급(음수) 표기, 인원 0 무실적 신고, 중도 입퇴사 달.
- **중복 실행**: 신고서는 저장물이 아니라 **조회 시점 계산**(부가세와 동일) — 재생성 개념 없음. 납부 체크만 저장.
- **마감**: 급여 배치를 신고 후 수정하면? — 신고서 화면에 "이 달 배치 마지막 변경일"을 적어 어긋남을 보이게.
- **기존 데이터**: 결정 101·102 항목별 명시 완료.
- **파급 화면**: §5.
- **외부 전송**: 세무사 엑셀은 다운로드까지만(메일 자동 발송은 범위 밖 — 급여 정보 유출 리스크).
- **인쇄/엑셀**: 모든 신고서에 엑셀(공용 ExcelMenu). **모바일 폭**: 신고서는 표 — 가로 스크롤 컨테이너.
- **되돌리기**: 납부 완료 체크 해제 가능(기존 동작 그대로). **해당 없음**: 다국어, 첨부파일.
