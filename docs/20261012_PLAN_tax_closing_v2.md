## ② 자문자답

1. **무엇을 기준으로 판단하나?**
   - 마감·수정신고의 기준 = **그때 저장한 신고본**(숫자 + 근거 자료 목록). 지금 자료로 다시 계산한 값이 '수정' 쪽이다.
   - 당초(신고본) ≠ 지금 계산 → "마감 뒤 바뀐 자료 N건" → 수정신고 대상. 세액이 줄면 **경정청구**, 늘면 **수정신고**(국세기본법 45조·45조의2).
2. **사용자는 왜 마감하나?** 홈택스에 낸 숫자와 장부를 묶어 두려고. 나중에 전표가 바뀌어도 "그때 뭘 냈는지"를 보여 줘야 한다.
3. **반대 경우?**
   - 마감 뒤 늦게 들어온 세금계산서 → 그 기간 자료가 바뀐다. 막을지(잠금), 받아 두고 경고할지.
   - 예정신고 누락분은 다음 확정신고 (7)(13)행에 넣는 길도 있다 → 수정신고만이 답이 아니다.
   - 수정신고를 두 번 → 차수(1·2…)가 있다. 비교 기준은 **직전 차수**.
4. **자동으로 못 푸는 것(사람에게 맡기고 화면에 적는다)**
   - 부동산임대 공급가액(임대 계약·보증금 간주임대료), 의제매입(면세 농산물 품목·한도), 대손(대손 사유·확정일), 공제받지 못할 매입세액의 사유 구분 일부 → **입력 칸**을 두고 "직접 입력"이라고 적는다.
   - 가산세 계산(무신고·과소·납부지연) → 세무사 확인. 화면에 참고 계산만.
   - 제출 자체 → 국세청 API 없음(결정 100 그대로). 홈택스에서 사람.

### 결정 258 — 신고본 저장 = 세무 '마감'
- **규칙**: 신고 화면의 「마감」 = 그 기간 신고서 숫자 + 부속서류 숫자 + 근거 자료 id 목록(전표·세금계산서·payroll_items)을 **신고본 1행**으로 저장.
  종류: 부가세(기수·예정/확정), 원천세(귀속·지급월), 간이지급명세서, 지급명세서, 일용 근로내용확인신고.
- **AS_IS ▶ TO_BE**: 늘 다시 계산 ▶ 마감한 기간은 **신고본을 먼저 보여 주고**, 지금 계산과 다르면 「바뀐 자료 N건 · 수정신고 만들기」.
- **잠금(사장님 확정: a)**: (a) 신고본만 저장, 자료는 열어 둠 — 늦게 온 계산서를 받을 수 있고 차이는 경고로 / (b) 그 기간 전표·급여까지 잠금.
  **추천 (a)** + 기존 월 마감 잠금은 그대로 별도. 이유: 세금계산서는 마감 뒤에도 들어오고, 막으면 장부가 틀린 채로 남는다. 차이를 숨기지 않고 보여 주는 쪽이 안전.
  단 **급여 재발송**은 마감된 지급월이면 "원천세 신고 마감된 달입니다 — 수정신고 대상이 됩니다" 확인을 띄운다.
- **적용 시점**: 배포 뒤 마감한 기간부터. **기존 데이터**: 신고본이 없으면 지금처럼 '계산값'으로 보이고 「마감」 버튼만 뜬다(과거 기간 소급 저장은 사람이 누를 때만 — 추측 백필 금지).
- **되돌리기**: 마감 취소 = 신고본 '취소' 상태(지우지 않음, 이력 유지). 권한 = 마스터 | /finance/tax-filing 쓰기.
- DB: `tax_returns`(company_id, kind, period_key, revision 0=정기·1~=수정 차수, status closed/cancelled, figures jsonb(행번호→금액·세액), schedules jsonb(부속서류), source_ids jsonb, filed_at, closed_by, note) + RLS(회사 소속 읽기 / 쓰기 = 마스터|세무 권한, RESTRICTIVE). **모티브 먼저 아님** — 사람이 누를 때만 행이 생기므로 데이터 자동 생성이 아니다. 화면은 전 회사 공통.

### 결정 259 — 수정신고 = 직전 차수 신고본 vs 지금 계산, 서식에 두 줄
- **규칙**: 이미지 18처럼 서식 한 칸에 **위 = 당초(직전 신고본), 아래 = 수정**. 다른 칸만 색. 이미지 17처럼 좌우 보기도 토글.
  세액이 줄면 제목을 「경정청구」로, 늘면 「수정신고」로 자동 표기(판단 기준을 화면에 적는다).
- 수정본을 마감하면 revision+1 신고본. 비교 기준은 늘 직전 차수.
- 가산세는 참고 계산(과소신고 10%·납부지연 일 0.022%)만, "세무사 확인" 표시.

### 결정 260 — 신고서 서식 화면(부가세·원천징수이행상황신고서·지급명세서)

## ④ 누락 점검 (PLANNING_METHOD ④)
- 권한: 마감·수정 = 마스터|/finance/tax-filing 쓰기. 보기 권한자는 신고본 열람만. 직원 기본 권한엔 없음(재무·인사 비노출 원칙).
- RLS: tax_returns·income_payments 신설 → 회사 소속 읽기, 쓰기 RESTRICTIVE. 주민번호는 기존 employee_rrn RPC만(평문 저장 금지).
- 역할: 세무사 계정(advisor) 읽기 허용 여부 — 기존 advisor_ro 패턴 따름.
- 빈 상태: 자료 0건 기간 마감 = 무실적 신고본(0원)으로 저장 가능.
- 경계값: 음수(환급)·0·소액부징수(1천원 미만)·단수(원 단위 절사).
- 중복 실행: 같은 기간 정기 신고본은 1개(unique company·kind·period·revision).
- 마감: 월 마감 잠금과 독립(결정 258 a).
- 기존 데이터: 소급 생성 안 함.
- 파급 화면: tax-filing 전 탭, VatReturn·VatReport, 급여 발송(재발송 확인), 세금 일정, 대시보드 '처리할 것', 전자신고 파일 2종.
- 외부 전송: 없음(파일·엑셀만).
- 인쇄·엑셀: 서식 화면 인쇄/PDF, 부속서류 엑셀.
- 모바일 폭: 서식 표는 가로 스크롤 허용(서식 칸 줄이면 못 읽는다).
- 되돌리기: 마감 취소(이력 유지).

## ⑤ 단계 (각 단계 끝에 실측·배포)
1. **기반**: tax_returns + 마감/취소 + 부가세 신고서·원천징수이행상황신고서 **서식 화면** + 수정신고 비교(당초/수정 두 줄). (DB·RLS → L)
2. **부가세 부속서류 A(자료 있음)**: 합계표 건별 드릴다운·계산서합계표 분리·신용카드 수령명세서/발행집계표·공제받지못할·건물등감가상각.
3. **부가세 부속서류 B(입력 필요)**: 부동산임대·의제매입·대손·경정청구.
4. **원천세 소득 확장**: 일용(고용형태+일당) · 기타/이자/배당 지급 기록 · 급여대장 신고본 첨부.
5. **지급명세서 체계**: 간이(월/반기)·연간·일용 지급명세서 분리 + 서식 화면 + 일정.
6. **일용 근로내용확인신고서 · 보수총액신고 · 보수월액 변경신고**.
7. **세무 이월**: 부가세 예정신고 미환급세액·원천세 차월이월환급세액을 직전 신고본에서 읽어 다음 신고서에 채움.

## 버린 안
- 마감 = 기간 자료 전부 잠금(b): 늦게 온 세금계산서를 못 받아 장부가 틀린 채 남는다. 차이를 보여 주는 쪽을 택함(사장님 확인 대기).
- 신고본 없이 '그때 자료로 다시 계산'(as-of 재계산): payroll_items 는 덮어쓰고 전표는 고쳐지므로 과거를 재현할 수 없다.
- 부속서류를 한 번에 전부: 입력형 서류(부동산임대·대손)는 쓰는 회사가 적어 자료 있는 것부터.
