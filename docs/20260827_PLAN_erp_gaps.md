## ① 채권·채무 연령표 (배포 2026-08-27)

### History
- 2026-06-12 거래처 원장(/partners/ledger) — 매출처/매입처 잔액(전표·이월 기준, RPC `get_partner_ledger_by_year`).
- 2026-08-19 요약 줄에 **매출 미수 경과 칩**(0–30/31–60/61–90/90+) — 합계뿐, 매출처만, 거래처별 분해 없음.
- 대시보드 `receivables-preview` 에 독촉 문구 복사가 있으나 원장과 따로 놀고 기록이 남지 않았다.

### 자문자답
1. **기준** — 전표처리된 세금계산서의 미정산 잔액(total − settled_amount), 경과일 = 오늘 − 발행일. 원장 칩과 같은 기준이라 숫자가 서로 맞는다. 지급기일 칸이 없으므로 발행일 기준(이카운트도 기본은 발행일).
2. **왜** — "누구한테 얼마가 얼마나 오래 밀렸나"를 한 표로. 독촉 우선순위와 대손 판단의 출발점.
3. **반대 경우** — 계산서 없이 전표로만 잡힌 채권(이월·수기)은 계산서 기준 표에 못 나온다 → 원장 보기로 안내(결정 53). 취소 계산서(마이너스)는 잔액 ≤ 0 이라 자연히 빠진다.
4. **자동으로 못 푸는 것** — 독촉 발송. 문구만 만들어 복사하게 하고 발송·기록은 사람.

## ② 재고자산·급여 전표 자동 초안 (배포 2026-08-27)

### History
- 생산 전표·매출원가 초안(결정 28~42)은 있으나 **기말 재고자산 계정이 실물 가치와 맞는지**는 아무도 안 봤다. 구매가 비용(원재료비·상품매입)으로 갔으면 재무상태표에 재고가 없다.
- 급여대장(payroll_items, 명세 발급 issued)은 있으나 전표는 사람이 일반전표로 따로 쳤다.

### 자문자답
1. **기준** — 재고: 기준일 층 원가 가치(입고 층 합 − 출고 원가 합, `_stock_value_asof`) vs 확정 전표의 재고자산 계정 잔액 → **차액만** 전표. 급여: 발급된 명세의 합계(총급여 = 실지급 + 공제).
2. **왜** — 재무상태표 재고자산·손익 매출원가를 맞추려고. 급여는 매달 같은 일을 손으로 치지 않으려고.
3. **반대 경우** — 차액 0이면 초안 없음. 이미 확정된 기간이면 예외(반려 후 재생성). 명세 미발급 달은 없음. 회사 부담 4대보험은 명세에 없어 **빠진다**(적요에 적음 → 사람이 고지서로 추가).
4. **못 푸는 것** — 품목이 제품/상품/원재료 중 무엇인지: 생산 층 있음=제품, 자재구성 구성품=원재료, 그 밖=상품. 애매하면 사람이 전표를 고친다.

## ③ 월마감 스냅샷 (배포 2026-08-27)

### History
회계마감 '잠금'(closing_checklists.locked)은 그 달 전표 입력만 막았다(PERIOD_LOCKED). 재무제표(reports/bs·pnl)는 항상 지금 전표로 다시 계산되므로 잠근 뒤 전표를 반려·정정하면 마감한 달의 숫자가 소리 없이 바뀌었다.

### 자문자답
1. **기준** — 잠금 순간의 확정 전표로 계산한 계정별 잔액(재무상태표: 연초~월말 누적)·손익(그 달 + 누적). 계산은 화면과 같은 lib(`journal-reports`)를 써서 숫자가 갈리지 않게.
2. **왜** — "마감했다"는 말이 숫자 고정을 뜻해야 세무사·투자자에게 낸 표가 나중에 안 바뀐다.
3. **반대 경우** — 잠근 뒤 정정이 꼭 필요할 때: 잠금을 풀고(unlock) 고친 뒤 다시 잠그면 그때 다시 찍힌다. 풀지 않고 바뀌면(다른 달 전표의 반려 등) 화면이 ⚠로 알린다.
4. **못 푸는 것** — 왜 달라졌는지. 계정별 차이만 보여 주고 원인은 전표 현황에서 사람이.

| 59 | 자동 마감(autoCloseMonth)은 completed 까지만 — 잠금(확정본)은 사람이 | — | — | — |

**버린 안**: 서버 함수로 스냅샷 — 손익 구간(section) 분류가 클라이언트 lib(account-nature)에 있어 SQL로 다시 쓰면 두 벌이 된다. 잠긴 달 전표 변경 자체를 DB에서 막기 — 반려는 이미 PERIOD_LOCKED 로 막히고, 다른 달 전표가 누적 잔액을 바꾸는 것은 막을 수 없어 '알림'이 맞다.

### 누락 점검
권한: RLS company_isolation + advisor 읽기전용(closing_checklists 와 동일). 빈 상태: 잠근 달 없음 안내. 경계값: 잔액 0 계정 제외. 중복: upsert(회사·월). 파급: reports/bs·pnl 조회 줄 버튼, lockClosingMonth. 되돌리기: 잠금 해제 후 재잠금.

## ⑤ 고정자산 (배포 2026-08-27)

### History
장비·차량·소프트웨어를 사면 비용으로 잡혔다. 옛 `vault_assets`(자산 보관함, 0건, 계정 연결 없음)는 2026-07-28 사이드바에서 내렸다.

### 자문자답
1. **기준** — 취득가·잔존가·내용월수·방법(정액 기본/정률)·상각 시작 월. 월 상각 = 정액 (취득가−잔존가)÷월수, 정률 장부가×2÷월수. 누계는 취득가−잔존가를 넘지 않는다.
2. **왜** — 재무상태표에 자산·누계액, 손익에 감가상각비가 달마다 자동으로 앉게.
3. **반대 경우** — 처분(상각 멈춤, 손익 전표는 사람), 이미 확정된 달(예외 → 반려 후 재생성), 무형(소프트웨어: 누계액 없이 자산 직접 차감·840), 계정 없음(예외로 알림).
4. **못 푸는 것** — 취득 전표(매입 세금계산서 전표에서 자산 계정 선택) · 처분 손익 전표(매각가·부가세) — 사람이 일반전표로.
