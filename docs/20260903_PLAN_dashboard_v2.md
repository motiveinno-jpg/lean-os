## 진단 (실측 화면 기준)
1. **벽돌 쌓기 재발** — 크기 조절 복원으로 높이가 제각각. 격자가 3열인데 바닥선이 한 줄도 안 맞는다.
2. **빈 상자가 자리를 먹는다** — 비어 있는 위젯이 내용 있는 위젯과 같은 크기. 첫 화면 12개 중 3개가 빈 상자.
3. **위계가 없다** — 신호·챙길 것·위젯 12개가 전부 같은 흰 카드 + 같은 머리("이름 · 전체보기 →"). 무엇이 중요한지 눈이 못 고른다.
4. **챙길 것이 '보고서'처럼 읽힌다** — 한 문장 결론 아래 색 숫자 8개짜리 문단, 그 아래 6줄. 할 일인데 체크할 수 없고, 누가·언제까지가 없다.
5. **알약 칩 난립** — 긴급/중요/권장·좋음/주의/위험·398일 지연·독촉·진행 … 색 칩이 20개 넘게 흩어져 시끄럽다.
6. **원본이 홈에 그대로** — 통장 거래 11줄(네이버 kodari +165만 …)은 홈에서 읽을 정보가 아니다. 요약(오늘 입금·출금·미분류)이 먼저다.
7. **작은 흐린 글자** — 10~11px 회색(--text-dim #A1A1AA)이 보조 문장 전부에 쓰여 읽히지 않는다.

## 자문자답
- **무엇을 기준으로 판단하는가** — 아침에 열어 **30초** 안에 ①안전한가 ②오늘 뭘 하나 ③더 볼 게 있나가 위에서 아래로 한 번에 읽히는가. 눈이 좌우로 헤매면 실패.
- **왜 위젯 형식인가** — 회사·역할마다 보고 싶은 것이 달라서. 이 목적은 유지한다. 바꾸는 것은 "자유 크기"가 아니라 **격자의 규율**이다.
- **반대 경우** — 위젯을 크게 보고 싶다: 1단/2단 높이 두 가지만 허용(자유 픽셀 금지). 빈 위젯을 그래도 보이고 싶다: 한 줄로 접혀 맨 아래에 묶인다(안 보이는 게 아니다).
- **자동으로 못 푸는 것** — 어떤 위젯이 누구에게 중요한가 → 프리셋(대표/회계/직원)이 첫 답, 이후 사람이 켜고 끈 것이 이긴다(기존). 챙길 것 완료 여부 → 사람이 체크(오늘 하루 기억).

## 결정
**149 — 격자 규율 (2026-09-03 사장님 확정: "크기 자유 조절은 없고, 이동은 자유롭게. 대신 데이터 잘리는 것 없도록")**
- 규칙: 3열 고정. **크기 조절 없음, 자리 이동은 자유(드래그, 격자 스냅).** 높이는 위젯이 내용에 맞춰 스스로 정한다 — 1단(232) / 2단(480) / 3단(728). 빈 위젯은 **한 줄(52px)** 로 접혀 격자 맨 아래에 모인다.
- AS_IS 자유 픽셀 크기 + 자유 자리 ▶ TO_BE 자리만 자유, 높이는 내용이 정함. 적용 시점: 배포 즉시. 기존 데이터: user_preferences.dashboard_grid 는 새 키 v4 로 시작(옛 배치의 x·y 순서만 승계, w·h 버림), 켜 둔 위젯 목록은 승계.
- 버린 안: 크기 자유 조절 유지 — 8/20 에 복원했던 이유는 **일정·할 일 위젯의 달력 아래가 잘려서**였다(사장님). 원인은 자유 조절이 아니라 "위젯이 내용보다 작게 그려진 것"이므로 결정 157 로 잘림 자체를 금지하고 조절은 없앤다.

**157 — 잘림 금지: 위젯 높이는 내용이 정한다**
- 규칙: 위젯은 **자기 내용이 다 들어가는 단**을 스스로 선언한다(달력 = 2단, 6주 격자가 통째로 들어가는 줄 높이 / 미수금·통장 = 1단 표 5줄 / 프로젝트 = 1단 5줄). 화면 어디서도 내용이 위젯 테두리에 잘려 보이면 결함이다.
- 넘치는 내용은 **자르지 않고 두 가지 중 하나**로: ① 표는 줄 수 상한 + 마지막 줄 "외 N건 →"(그 화면으로) ② 달력·목록처럼 상한을 둘 수 없는 것은 위젯 안 세로 스크롤(머리 줄 고정, 스크롤바 보임).
- 검증: 배포 전 위젯마다 `scrollHeight > clientHeight` 를 재서 스크롤 허용 위젯이 아니면 0 이어야 한다(zoom 안 실측 규칙과 같은 방식). 달력은 6주가 되는 달(2026-08·2026-11)로 실측.
- AS_IS 달력 아래 잘림(자유 조절로 사람이 늘려야 보임) ▶ TO_BE 처음부터 다 보이는 2단. 적용 시점: 2단계. 기존 데이터: 해당없음.

**150 — 세 층의 생김새를 다르게**
- 층 1 **신호 띠**: 카드가 아니라 얇은 띠(테두리·그림자 없음). 6칸 사이 세로 실선, 상태는 **숫자 아래 3px 색선 + 한 단어**(좋음은 색 없음). 부제는 12px 이상.
- 층 2 **오늘 챙길 것(왼 8열) + 오늘 한눈(오른 4열)**: 오른쪽은 세금 D-day·결재 대기·오늘 일정을 **한 카드 안 세 절**로. 비면 절이 한 줄로 준다.
- 층 3 **위젯 격자**: 결정 149.
- AS_IS 세 층 모두 흰 카드 ▶ TO_BE 띠 / 큰 카드 2 / 작은 카드 격자.

**151 — 챙길 것 = 체크리스트**
- 줄 = **우선순위 세로선**(긴급 빨강·중요 주황·권장 없음) + 제목(13.5px) + 근거 한 줄(12.5px 회색: 누구·얼마·언제) + 오른쪽 **실행 버튼(그 화면 →)** + 왼쪽 **완료 체크**.
- 한 문장 요약은 **한 줄**로, 색 숫자는 최대 2개. 근거 5줄은 '근거 보기'로 접음(기존).
- 완료 체크: DB `briefing_checks(company_id, user_id, item_key, date)` — 다음날 초기화. 체크된 줄은 흐리게 아래로.
- 적용 시점: 2단계. 기존 데이터: 브리핑 로직·권한(/dashboard:briefing)·30분 쿨타임 그대로.
- 버린 안: 담당자 배정 — 홈에서 사람을 고르게 하면 결재/프로젝트와 역할이 겹친다. 체크만.

**152 — 상태 색 문법: 칩 금지**
- 알약 칩(배경색+글자) 대신 **세로선 / 점 / 글자색** 셋만. 좋음은 색을 쓰지 않는다(검정). 주의 주황, 위험 빨강, 진행·정보 보라(브랜드).
- 예: 미수금 줄 "398일 지연" 빨간 칩 ▶ 금액 옆 작은 빨간 글자 "398일". '독촉' 버튼은 줄 hover 때만.
- AS_IS 칩 20+ ▶ TO_BE 칩 0. 적용: 층 1·2 는 1단계, 위젯은 2단계.

**153 — 위젯 몸통은 세 가지 꼴**
- ① 표 5줄(이름 · 값 · 보조) ② 숫자 2×2(각 칸 값 + 막대) ③ 진행 목록(제목 · 상태점 · 값).
- 통장 거래: ① 대신 **요약 3칸**(오늘 입금 / 출금 / 미분류) + 최근 3건. 카드 사용도 같음.
- 버린 안: 위젯마다 자기 모양 — 지금의 원인.

**154 — 머리 줄 통일**: `이름  보조숫자` … `상태점 n시간 전` … `→`. '전체보기' 글자 삭제, 화살표 하나. 동기화 ↻ 는 통장·카드만(기존 결정 3).

**155 — 타이포 스케일**: 28(신호 값) / 15(카드 제목·챙길 것 제목) / 13.5(본문) / 12.5(보조) / 11.5(라벨 최소). 회색 글자는 `--text-muted`(#6B7280) 이상, `--text-dim` 은 라벨에만.

**156 — 프리셋·보기 설정 유지**: 대표 9 / 회계 9 / 직원 6 (8/19 결정 4 목록 그대로). '편집'은 자리 드래그 + 켜고 끄기만(크기 손잡이 없음).
