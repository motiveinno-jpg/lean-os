# 통장 줄 처리 — 계정과목 매핑 → 증빙 연결 · 일반전표 · 장부 제외 (2026-08-27)

## 1. History — 왜 이 모양이었나
- 2026-05 통장 › 거래내역의 상태 칩(미매핑/자동/수동/무시)은 `transaction-mapping-popover` 를 열어 **분류(category) 글자**만 적었다(`mapBankTransaction`). 전표를 만들지 않아 "매핑 완료" 뒤에도 장부에는 아무것도 없었다.
- 전표는 **수집·전표 › 통장 탭**(`post_bank_manual_voucher`, 2026-08-12)에서, 계산서 짝은 **거래 매칭 화면**(`invoice_settlements` 즉시 confirmed)에서 따로 했다. 한 줄을 끝내려고 세 화면을 돌았다.
- 2026-08-19 통장 화면 기본을 '미전표'로 바꾸며 상태 칩에 전표됨·장부 제외가 붙었지만, 칩을 누르면 여전히 분류 팝오버였다.

## 2. 자문자답
1. **무엇을 기준으로 판단하나** — 통장 한 줄이 장부에 어떻게 들어가느냐: (a) 계산서가 있는 돈 → 정산 전표(외상매출금/외상매입금 ↔ 보통예금) (b) 계산서 없는 돈 → 일반전표(비용/수익 ↔ 보통예금) (c) 장부 밖 돈 → 제외. 셋 중 하나이고 겹치지 않는다. '분류'는 이 셋 어디에도 없다.
2. **왜 하나** — 미수·미지급을 지우고 재무제표를 맞추려고. 분류 글자는 재무제표에 안 들어간다.
3. **반대 경우** — 분할 입금·합산 입금·원천세 차감: 계산서 남은 금액보다 적게/여러 번 연결한다(금액 칸). 계산서가 아직 안 온 선수금: 일반전표(선수금)로. 같은 금액 계산서가 수두룩: 후보로 올리지 않고 직접 찾기(수집·전표 통장 탭과 같은 기준).
4. **자동으로 못 푸는 경우** — 어떤 계산서와 짝인지는 결국 사람이 안다. 그래서 **초안(연결 대기)까지만 자동, 확정은 사람**.
