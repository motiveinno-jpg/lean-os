# 오너뷰 블로그 작성 규칙 (사람·클라우드 루틴 공통)

블로그는 검색으로 들어온 사장님이 **질문의 답**을 얻고, **오너뷰 실제 화면**을 보고, **무료로 시작하기**까지 가는 길이다.
글 한 편 = `content/blog/<slug>.md` 하나 + `public/blog/<slug>/` 캡처 몇 장. 푸시하면 www.owner-view.com/blog 에 올라간다.

## 1. 주제 고르기 — 사장님이 실제로 검색하는 질문
우선순위 순. 이미 쓴 주제는 `content/blog/` 에 있으니 겹치지 않게.
1. 법인카드 부가세 공제가 안 되는 가맹점(간이·면세) 걸러내기
2. 사업용 신용카드 홈택스 등록, 안 하면 생기는 일
3. 미수금 독촉, 계산서 발행 뒤 입금 안 될 때 순서
4. 통장 하나 연결하면 아침에 무엇이 보이나(잔고·미수금·오늘 낼 돈)
5. 5인 미만 회사 연차, 주휴수당 계산과 근태 기록
6. 정기 지출(월세·보험·구독) 빠짐없이 챙기는 법
7. 세무사에게 자료 넘기기 전 30분 정리법
8. 전자세금계산서 발행·수취 흐름과 자주 나는 실수
9. 반차·지각·결근, 근태 규칙을 처음 정할 때
10. 법인카드 개인 사용 구분, 장부 제외 처리

## 2. 글 구조 (그대로 따른다)
1. **제목**: 질문 그대로. 40자 이내. 예) "법인카드 부가세, 왜 어떤 가맹점은 공제가 안 될까"
2. **첫 문단**: 답을 먼저 말한다. 3문장 안에.
3. **왜 그런지**: 법·제도 설명은 사실만, 3~5문단. 확실하지 않은 숫자·조문은 쓰지 않는다.
4. **손으로 하면**: 지금 사장님이 엑셀·홈택스에서 하는 방법을 한 번 짚는다(공감).
5. **오너뷰에서는**: 실제 캡처 1~3장과 함께 어디를 눌러 무엇이 보이는지. 화면·탭·칸 이름을 그대로 쓴다.
6. **정리**: 핵심 3줄.
7. CTA 는 페이지가 자동으로 붙인다 — 본문에 "가입하세요"를 쓰지 않는다.

## 3. 문체
- 토스식 해요체. "~해요 / ~돼요 / ~이에요". 격식체("~합니다")와 구어("돌립니다")는 쓰지 않는다.
- 짧고 담백하게. 과장·최상급("완벽", "최고") 금지. 경쟁사 이름 거론 금지.
- 가격·요율·건수 같은 숫자는 랜딩 `content.ts` 와 다르게 쓰지 않는다. 모르면 쓰지 않는다.
- AI 가 썼다는 흔적("이 글에서는 ~를 알아보겠습니다", "결론적으로")을 남기지 않는다.

## 4. 캡처 규칙
- `node scripts/blog-capture.mjs <slug> '<JSON>'` — 운영 화면을 QA 시드 계정(샘플 자료, 개인정보 없음)으로 찍는다. 다른 회사 계정은 절대 쓰지 않는다.
- 항목: `{ name, path, click?: ["탭 글자"], waitMs?, clip?: "css 선택자" }`. 표만 필요하면 `clip: ".ev-scroll"`.
- 캡처에 투어 말풍선·토스트·"1 Issue" 같은 개발 표시가 끼면 다시 찍는다. 운영 도메인에서 찍으면 개발 표시는 없다.
- 첫 캡처를 `cover` 로 쓴다(목록 카드와 공유 이미지). 1440×900 이 기본.

## 5. 파일 규칙
```
---
title: 법인카드 부가세, 왜 어떤 가맹점은 공제가 안 될까
description: 120자 이내, 검색 결과에 그대로 보인다
date: 2026-09-04
tags: 부가세, 법인카드
cover: /blog/card-vat-deduction/card-tab.png
---
본문(마크다운). 이미지는 ![설명](/blog/<slug>/이름.png)
```
- slug 는 영문 소문자·하이픈만. 파일명 = slug.
- 표는 마크다운 표, 강조는 굵게만.

## 6. 올리기
1. `git add content/blog/<slug>.md public/blog/<slug>` — 경로를 명시해 add 한다(`git add -A` 금지).
2. 커밋 제목: `content(블로그): <제목>`. 본문에 지시 출처·날짜 꼬리표를 쓰지 않는다.
3. `git fetch origin && git rebase origin/main` 뒤 `git push origin main`. Vercel 이 자동 배포한다.
4. 배포 뒤 `https://www.owner-view.com/blog/<slug>` 를 한 번 연다. 캡처가 깨졌으면 다시 찍어 올린다.

## 7. 클라우드 루틴이 할 때
- 주 1편. 위 1번 목록에서 아직 없는 주제 중 첫 번째.
- 캡처는 루틴 환경에서 브라우저가 되면 직접 찍고, 안 되면 `public/blog/_library/` 의 기존 캡처를 쓴다(이 폴더는 이 PC 에서 `scripts/blog-capture.mjs` 로 갱신).
- 글을 올린 뒤 결과(제목·주소·캡처 수)를 아침 점검 메일 수신자에게 알린다.
