# 오너뷰 디자인 시스템

> 2026-09-07 신설. 사장님 지시 — "디자인·UI 구성·일러스트 능력을 올리려면 뭐가 필요한가"에 대한 답의 하나.
> **색·간격·타이포가 `globals.css` 와 `landing*.css` 에 흩어져 있어서 화면을 만들 때마다 새로 정했다.**
> 그 탓에 "현재 디자인 시스템에 맞춰 배포하라"는 지적이 반복됐다(자동 메모리 `feedback-match-current-design-system`).
> 이 문서는 **이미 코드에 있는 값을 옮겨 적은 것**이다. 여기서 새로 지어낸 값은 없다.

## 이 문서의 자리

| 무엇 | 어디 |
|---|---|
| **화면 구성 규칙**(조회 줄·검색조건·표·탭·팝업·버튼 개수) | `CLAUDE.md` 의 「조회 화면 표준」— **그쪽이 원본이다.** 여기서 다시 적지 않는다 |
| **색·타이포·간격·그림자 값** | 이 문서 |
| **일러스트·랜딩 레이아웃 규칙** | 이 문서 |
| **결정 이력** | `~/motive-brain/decisions.md` |

값을 고칠 때는 **코드를 고치고 이 문서를 같이 고친다.** 문서만 고치면 거짓말이 된다.

```
--primary        #4F46E5   indigo-600 — 1차 버튼·활성·강조. 전 라우트가 이걸 쓴다
--primary-hover  #4338CA
--primary-light  #EEF2FF   사이드바 활성·칩 배경
--brand          #4F46E5   --primary 와 같은 값 (2026-05-27 인디고 리브랜드로 정렬됨)

--bg             #FAFBFE   캔버스. 흰색이 아니라 인디고-그레이 틴트 — 흰 카드가 떠 보이게
--bg-card        #FFFFFF   카드는 솔리드 흰색 (2026-07-29 반투명에서 전환)
--bg-surface     #F4F6FB   입력칸·hover
--border         #E5E8F0
--border-light   #D8DCE8

--text           #18181B   zinc-900
--text-muted     #52525B   zinc-600
--text-dim       #A1A1AA   zinc-400
```

**상태색** — 뜻이 정해져 있다. 시리즈 색으로 쓰지 않는다.

```
--success #059669   --warning #D97706   --danger #DC2626   --info #2563EB
--critical #B91C1C  --accent #FACC15 (Granter 시그니처 노랑, 아주 드물게)
```

**시각화 팔레트** — 큰 색면(막대·도넛)은 상태색보다 채도를 낮춘 이쪽을 쓴다. 그래프가 튀지 않게.

```
--viz-brand #5B54D9  --viz-pos #3F9B7C  --viz-warn #C48A38  --viz-neg #CB5F58  --viz-info #5480BE
시리즈 8칸: --viz-1 #5B54D9  --viz-2 #B06A00  --viz-3 #0F8FA3  --viz-4 #C2455E
            --viz-5 #6E8F0F  --viz-6 #B45CC9  --viz-7 #2E9E86  --viz-8 #4A8FE7
```

> ⚠️ 시리즈 8칸은 **눈으로 고른 게 아니다.** 색약(적/녹/청)에서의 구분·명도대비·채도를 계산으로 검증해
> 통과한 조합이다(2026-08-06). 순서대로 쓰고 돌려쓰지 않는다. 마음대로 바꾸지 말 것.

### 1-2. 랜딩 (`src/app/landing-v7.css` 의 `.lp7-root`)

앱과 **같은 인디고**를 쓰되 이름이 다르다. 랜딩은 `:root` 를 건드리지 않고 자기 안에서만 정의한다
— 그래야 옛 랜딩(lp4~lp6)이 영향을 안 받는다.

```
--lp7-brand #4f46e5   --lp7-brand-ink #4338ca   --lp7-brand-soft #a5b4fc
--lp7-ink #0b0b0f  --lp7-ink2 #3a3a46  --lp7-ink3 #6b6b78  --lp7-ink4 #8a8a96
--lp7-line #e6e8f0  --lp7-line2 #f0f1f6
--lp7-canvas #ffffff  --lp7-canvas2 #f5f6fb
```

> 회색 바닥 `#f5f6fb` 는 **순회색이 아니라 남색 쪽으로 기운 회색**이다. 브랜드와 같은 계열이라
> "고른 색"으로 읽힌다. 순회색(#f5f5f5)을 쓰면 아무 생각 없이 놓은 것처럼 보인다.

### 1-3. 사이드바 그룹 색


## 3. 간격 · 반경 · 그림자 · 컨트롤

```
--control-h      2.5rem (40px)   버튼·입력 기본 높이
--control-h-sm   2rem   (32px)   btn-sm

--radius-card    20px            카드
--pf-radius      20px            프로젝트 화면 카드

--shadow-sm  0 1px 2px rgba(0,0,0,.04)
--shadow-md  0 4px 16px -4px rgba(0,0,0,.06), 0 1px 4px -1px rgba(0,0,0,.04)
--shadow-lg  0 16px 32px -12px rgba(0,0,0,.10), 0 4px 12px -4px rgba(0,0,0,.06)

--content-max       900px    좁은 콘텐츠·폼·명세
--content-max-wide  1100px   표·관리 화면
```

### ⚠️ 앱 전체가 `zoom` 안에 있다

```
--app-zoom: 1.05      /* .app-zoom { zoom: var(--app-zoom) } */
```

`zoom` 안에서는 `100vh` 가 zoom 배로 늘어난다. 뷰포트에 맞춰 잡는 높이는 **전부
`calc(100vh / var(--app-zoom) …)`** 로 나눠 적는다. 배포 전마다 사이드바 bottom 과 본문 상자 bottom 을
`getBoundingClientRect` 로 실측해 같은지 확인한다(2026-08-26 사장님 "무조건 확인").

## 4. 컴포넌트

화면 구성 규칙은 **`CLAUDE.md` 의 「조회 화면 표준」이 원본**이다. 여기서는 클래스 이름만 적는다.

| 부품 | 클래스 | 비고 |
|---|---|---|
| 버튼 | `.btn-primary` `.btn-secondary` `.btn-ghost` `.btn-danger` + `.btn-sm` | **자체 색 버튼 금지.** 파란(확정) 버튼은 화면에 하나 |
| 표 | `.ev-table` `.ev-lined` + `SortableTh` | 화면별 `min-width` 는 `table.xxx` 로 |
| 갈래 탭 | `.collect-tabs` | 상자 **안** 맨 위 파란 밑줄 한 줄. 상자 밖 `seg-bar` 금지 |
| 조회 3줄 | `src/components/query-kit.tsx` | 새 툴바를 만들지 말고 이것을 쓴다 |
| 빈 상태 | `.collect-empty` | 상자 안 상자 금지 |
| 카드 | `.glass-card` | 목록에는 쓰지 않는다(표를 쓴다). '보기' 옵션일 때만 |

### 클래스 이름 규칙

`className` 에는 **시맨틱 마커 이름만** 남기고 스타일은 `globals.css` 에 `@apply` 로 뺀다
(자세한 것은 `CLAUDE.md` 「클래스 네이밍」과 `.claude/skills/classname-cleanup`).

> ⚠️ **`@apply` 에는 Tailwind 유틸리티만 넣는다.** `mono-number` 같은 우리 커스텀 클래스를 `@apply` 하면
> CSS 전체가 깨져 앱 전 화면이 500 이 된다. tsc·lint 가 못 잡는다(자동 메모리 `feedback-apply-only-tailwind-utilities`).

## 5. 아이콘

**지금 상태 (2026-09-07 실측)** — 저장소에 손으로 그린 `viewBox="0 0 24 24"` SVG 가 **290개**다.
아이콘 라이브러리가 없다. 그래서 화면마다 굵기·모서리·크기가 미묘하게 다르다.

**규칙**

- **새로 만드는 화면은 `lucide-react`** 를 쓴다(MIT, 굵기·격자가 통일돼 있다).
- **기존 290개는 건드리지 않는다.** 고장 안 난 것을 리팩터링하지 않는다(`CLAUDE.md` 「정밀한 변경」).
  그 화면을 어차피 손볼 때 그 김에 바꾼다.
- 크기는 16 / 20 / 24 셋만. 획 굵기 1.8(작은 것) 또는 2(큰 것).

## 6. 일러스트

2026-09-07 랜딩 v8 목업에서 정했다. **오두를 벤치마킹하되 그들의 일러스트는 쓰지 않는다** —
저작물이고, 다색 일러스트를 쓰면 우리 앱 UI 와 결이 달라져 랜딩만 딴 제품처럼 보인다(결정 195 (a)).

| 규칙 | 내용 |
|---|---|
| **선 위주** | 면을 크게 칠하지 않는다. 채우기는 `#eef0ff` 같은 아주 옅은 틴트만 |
| **획** | 1.4 ~ 2px, 둥근 끝(`stroke-linecap="round"`) |
| **색** | 브랜드 인디고 하나가 주인공. 회색(`#dfe2ef` `#c7cbf5`)으로 받친다. 초록·주황은 **상태를 뜻할 때만** |
| **움직임** | 선을 따라 점이 흐르는 정도. `<animateMotion>` 로 가볍게. 과하면 AI 가 만든 페이지처럼 보인다 |
| **금지** | 손그림 낙서 장식(결정 195 (b) — 담백한 톤과 충돌) · 다색 아이소메트릭 · AI 생성 사진 |
| **사람** | 실제 고객 사진이 아니면 사진을 쓰지 않는다. 기하학 아바타로 대신하고 자리표시자라고 화면에 적는다 |

**지금까지 그린 것** (랜딩 v8 목업 `landing-v8.html` 안)
흐름 배경(자료가 한 점으로 모임) · '아홉 → 하나' 도해 · AI 파이프라인 · 스팟 일러스트 5장 ·
메뉴 아이콘 32종 · 아이콘 벽 · 점 격자 배경 · 곡선 리본 · 기하 아바타.
