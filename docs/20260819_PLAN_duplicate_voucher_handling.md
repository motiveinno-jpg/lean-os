# 중복 의심 전표 처리 기획 — "장부에 안 올리고 처리됨으로" (2026-08-19, 사장님 요청)

## History
- 통장·카드·세금계산서 → 전표 RPC 는 `journal_entry_id` 가 있으면 ALREADY_POSTED 로 막는다(2026-06-25). 화면도 '전표됨' 배지·비활성.
- 일반전표(손으로 치는 전표)는 통장·카드 거래와 연결이 없어 같은 돈이 두 번 오를 수 있었다 → 2026-08-19 ① 저장 시 중복 의심 경고 ② '통장·카드 불러오기'(불러온 거래에 전표를 걸어 연결) 반영.
- 사장님 추가 요청: 중복 의심 팝업에서 **"전표처리는 되고 장부에는 반영 안 되게, 리스트에서는 사라지게"** 하는 길.

## 자문자답
- 기준: 두 가지 '처리'를 가른다 — **장부 처리**(전표를 만들어 재무제표에 오름) vs **정리 처리**(이미 장부에 있는 돈이라 이 거래는 '끝난 것'으로만 표시). 중복은 후자다.
- 왜: 자동 전표 + 사람이 친 전표가 겹칠 때, 사람은 "이 거래는 이미 반영됐어, 목록에서만 치워 줘"를 원한다. 장부에 또 올리면 이중 계상.
- 반대: 정말 다른 거래(같은 날 같은 금액이 우연히 둘)일 수 있다 → 그때는 그대로 새 전표. 그래서 팝업은 **세 갈래**여야 한다.
- 자동으로 못 푸는 것: 어느 전표가 진짜인지 — 사람이 고른다. 정리 처리한 건은 되돌릴 수 있어야 한다.

## 결정(제안)
1. **중복 의심 팝업 = 세 갈래** (일반전표 저장 시, 불러오기 없이 친 전표에만):
   - `그대로 새 전표 저장` — 다른 거래다.
   - `이미 있는 전표에 연결` ⭐ — 새 전표를 **만들지 않고**, 지금 입력한 내용은 버리고, 목록의 기존 전표(#N)를 이 통장/카드 거래의 전표로 건다(`journal_entry_id = 기존 entry`). 장부 불변, 거래는 '전표됨'으로 사라짐. **사장님이 말한 "장부 반영 없이 처리"의 정확한 뜻**.
   - `취소` — 다시 본다.
   AS_IS: 확인/취소 두 갈래 ▶ TO_BE: 세 갈래. 적용: 일반전표 저장 흐름. 기존 데이터: 영향 없음.
2. **통장·카드 목록의 '장부 제외 처리'** — 중복이 아니어도 "이 거래는 전표를 만들 필요 없다"(예: 계좌 간 이체 이미 반대편에서 처리, 개인 지출 반환)가 있다. 통장/카드 거래내역·수집·전표의 줄 동작에 **`장부 제외`**(사유 필수: 중복 / 이체 / 개인 / 기타) 를 둔다. 표시: `journal_entry_id` 는 비운 채 `ledger_excluded_reason` 을 적고, 목록 기본(미전표/미처리)에서는 사라지며 검색조건 '상태 = 제외' 로 다시 본다. 되돌리기 = 사유 지움.
   - 통장은 이미 `is_auto_transfer`(자동이체 표시)·`settlement_status`(수금 매칭) 가 '처리됨' 축에 있다 → '장부 제외'는 이 축의 일반형. 수집·전표 BankTab 의 doneOf 에 포함.
   - DB: `bank_transactions.ledger_excluded_reason text`, `card_transactions.ledger_excluded_reason text` (RLS 변경 없음, 마이그레이션 1건).
3. **어디에도 안 보이는 것은 없다** — 제외/연결 처리한 건은 수집·전표 검색조건 '상태 = 제외' 와 통장·카드 거래내역 '상태 = 제외' 로 언제든 본다(엑셀 포함). 손익 현황 '미처리 N건' 셈에서는 뺀다(countUnposted 가 제외 사유 있는 건을 빼도록).
4. **매입매출전표**도 같은 팝업(세금계산서·카드 → 전표 만들 때 같은 날·같은 금액 전표 있으면). 2단계.
5. **이름**: 버튼은 '장부 제외' (사장님 표현 '강제 회계 반영' 은 반대로 읽힐 수 있어 — 실제로는 회계에 안 올리는 것). 팝업 안 문장: "이미 있는 전표에 연결(장부 변화 없음, 목록에서 사라짐)".

## 버린 안
- 금액 0 전표를 만들어 '전표됨'으로 — 전표 수만 늘고 재무제표에 0원 줄이 남는다.
- 자동으로 중복을 합치기 — 어느 쪽이 진짜인지 기계가 못 정한다(우연히 같은 금액).

## 누락 점검
권한: 전표 저장 권한과 동일(관리자) · RLS: 새 칸만, 정책 변경 없음 · 빈 상태: 해당 없음 · 경계값: 같은 날 같은 금액이 여러 건 → 목록에서 하나 고르게 · 중복 실행: 연결은 `is('journal_entry_id', null)` 조건으로 한 번만 · 마감: 잠긴 기간의 거래는 연결·제외 불가(전표와 같은 규칙) · 기존 데이터: 영향 없음 · 파급: 수집·전표 BankTab/EvidenceTab doneOf, 통장·카드 거래내역 상태 칩, countUnposted, 손익 현황 BasisNote · 엑셀: 상태 열에 '제외(사유)' · 되돌리기: 사유 지움 / 연결 해제(전표는 그대로).
