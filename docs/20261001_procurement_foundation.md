# 모티브 나라장터 입찰 검토 — 기본 틀

작성일: 2026-10-01. 코드 위치: `~/Dev/lean-os`. 화면 주소: `/procurement`.

현재 상태는 **로컬 구현·검증 단계**입니다. 운영 DB 적용, 사이트 배포, 나라장터 실호출, 실제 이메일 발송, 예약 실행은 아직 하지 않았습니다. 화면 이미지의 회사·공고는 검증용 가상 자료이며 모티브의 실제 실적이 아닙니다.

## 구현한 흐름

1. 오너뷰 로그인 사용자 소속에서 회사를 결정합니다. 요청 본문에 다른 회사 ID를 넣어도 사용하지 않습니다.
2. `companies`의 회사명·사업자번호·대표자·주소·전화·팩스·업종·업태·종목을 읽습니다. `company_profile_ext`의 개업일·규모·인증 기록도 표시합니다. 회사 기록에 있는 인증은 증명서 확인 전에는 입찰 자격으로 확정하지 않습니다.
3. 오너뷰 파일보관함의 파일 목록을 읽어 회사 증빙과 연결할 수 있습니다. 파일명만 보고 실적·자격 보유를 확정하지 않습니다.
   원본에 문제가 발견되면 사유를 남겨 검증을 철회할 수 있습니다. 자료는 보존하고 연결된 평가를 재검토 대상으로 표시합니다.
4. 공고를 수동 등록하거나 나라장터 용역 검색 어댑터로 수집합니다. 공고번호·차수·내용 해시별 이력을 보존합니다. 최신 차수만 검토 목록에 표시합니다.
5. HWP/HWPX/PDF/DOCX/XLSX/XLS/TXT/CSV/MD를 첨부해 글자를 추출합니다. 10MB·문서당 20만 자·합계 70만 자 한도를 넘으면 잘라 저장하지 않고 안내합니다. 추출 후 원본 전체 대조 상태는 기본 미확인입니다.
6. 원문 위치와 실제 있는 문장, 회사 증빙, 판정 이유를 붙여 자격·점수·제출서류를 검토합니다.
   평가 당시 회사정보·증빙·추천 기준의 사본을 함께 저장합니다. 이후 자료가 변경되어도 예전 판단이 어떤 자료에 근거했는지 확인할 수 있습니다.
7. 검토 저장 후 회사가 진행·보류·제외를 결정합니다. 진행에는 최신 공고와 회사자료 기준, 자격 충족, 평가와 제출 목록 확정이 필요합니다.
8. 진행 결정과 동시에 회사 기본정보·기획 목차·조건 대응표·제출서류 체크리스트를 담은 Markdown 초안을 생성합니다. 결정·초안은 같은 트랜잭션으로 저장합니다.
9. 메일 미리보기에는 공고별 예산·마감·자격·점수·판단 이유·원문 인용·증빙명·보완 사항이 들어갑니다. 확인한 본문이나 수신자가 바뀌면 다시 미리보기를 확인해야 합니다.
10. 공고 수집과 메일 발송 이력을 남깁니다. 메일은 공급사 접수와 실제 수신을 구분합니다.

## 확정하지 않는 조건

- 필수 자격 미확인 또는 미충족.
- 원문 전문·제안요청서·첨부서식 누락 또는 원본 대조 미완료.
- 인용한 문장이 해당 원문에 존재하지 않음.
- 회사 증빙이 미확인·만료·유실 또는 해당 평가항목과 분류가 맞지 않음.
- 정확한 마감일시가 없거나 이미 마감·취소됨.
- 평가항목·제출서류 목록 미확정.
- 공고 내용·차수·회사 기본정보·증빙·추천 기준이 이전 평가와 달라짐.

미확인은 0점과 다릅니다. 다섯 항목의 배점은 유사실적 30 / 수행역량 25 / 수익성 20 / 일정·여력 15 / 제안경쟁력 10입니다. 필수조건과 검토 근거가 완료되기 전에는 종합점수를 확정하지 않습니다. 점수는 지원 우선순위이며 낙찰 확률이 아닙니다.

제출서류가 준비되지 않은 경우에는 준비·검수 경고를 남깁니다. `진행`은 입찰 준비를 시작하는 결정이며 제출 완료를 의미하지 않습니다.

## 이번 기본 틀에 포함되지 않은 부분

- AI가 공고 전문을 읽어 조건과 점수를 자동 제안하는 연결. 현재는 사람이 입력·검토한 근거를 구조적으로 검증하는 기반입니다.
- 기존 사업 자료의 의미 검색·유사실적 자동 연결·평가 기준 보정.
- 나라장터의 오래된 진행 공고, 정정·취소·마감 변경을 전수 감시하는 작업. 현재 어댑터는 최근 7일 게시된 용역 공고를 대상으로 합니다.
- 첨부파일 자동 다운로드·원본 저장·OCR·표/이미지 해석과 페이지별 출처 추적. 지금은 직접 첨부한 문서의 글자 추출과 원본 대조 기록입니다.
- 공고별 최종 HWP/HWPX/DOCX/PDF/PPTX 제작, 기관 지정 서식 편집, 산출물·인력·원가의 실제 기획.
- 전자서명·날인·가격 확정·나라장터 최종 제출.
- 메일 반송/수신 이벤트 자동 수집 및 별도 장애 알림 채널.
- 실시간 즉시 알림, 공휴일·주말 예외, 예산/지역/제외어 필터, 데이터가 대량으로 누적된 경우의 기간별 화면 페이징.

이 부분들은 자료와 실제 공고로 검증하면서 다음 단계에 연결해야 합니다. 지원 자격 또는 수행 가능성이 부족한 상태를 자동으로 낙관 평가하지 않습니다.

## 필요한 자료

현재 인력은 사용자가 지정한 오너뷰를 기준으로 직원 상태·입사/퇴사/계약종료일, 부서·직책·직무를 읽습니다. 프로젝트 할 일의 대표/공동 담당을 연결하고 보관 프로젝트·완료 단계·메모를 제외한 배정 업무를 보여줍니다. 프로젝트별 사용자 지정 완료 단계도 따릅니다. 급여·계좌·주민번호는 조회하지 않습니다. 인력 명단과 업무 수는 참고 정보이며 가용 시간과 전문 역량을 자동 증명하거나 평가 점수를 자동 부여하지 않습니다. 현재 인력 명단을 따로 보내 달라는 요청은 해제합니다.

사용자가 제공한 실제 사업 목록을 분석한 뒤 회사 자료 JSON 가져오기와 실적 기반 사전 분류를 추가했습니다. 실적에는 과업 태그·수행중/기간종료·회사/이전회사/미확인 귀속·중복 의심 그룹·금액 누락과 출처를 보관합니다. 회사 사업자번호가 일치할 때만 원자적으로 가져오며 동일 자료를 중복 저장하지 않습니다. 가져온 자료는 공식 증빙 확인 대기입니다.

공고 화면과 메일은 ‘수행 가능 후보 / 추가 확인 필요 / 수행 어려움 후보’를 상세 자격·점수와 별도로 보여줍니다. 원문에서 식별한 업무와 관련 실적을 연결합니다. 전문 미확보·중복만 존재·귀속 미확인·조건부 현장/기술 업무는 확인 대상으로 분류합니다. 전문 개발·시공 등 직접 수행 근거가 부족하면 어려움 후보로 표시하지만 자동 자격 탈락을 뜻하지 않습니다. 규칙 기반 문장 탐색이므로 원문의 요구·제외·발주처 제공 여부를 대조해야 하며 AI 전문 독해를 대체하지 않습니다.

회사 원본·분석·가져오기 JSON은 추적하지 않는 `deliverables/procurement/company-source/`에 보관합니다. 실제 사업자번호·연락처·프로젝트 내역은 공유 코드에 내장하지 않았습니다. 시트 변경의 정기 동기화는 아직 연결하지 않았습니다.

[자료 요청 목록](./20261001_procurement_intake.md)의 항목마다 **보유 / 미보유 / 해당 없음 / 확인 중**으로 답해 주세요. 모두 한 번에 정리할 필요는 없습니다. 기존 원본을 먼저 보내면 확인된 내용부터 채웁니다.

4. 과거 사업 원본 자료. 사업별로 발주처·금액·기간·직접 수행 범위·실적증명·결과물을 함께 주면 정확도가 높아집니다.

API 키, 인증서 비밀번호, 메일 비밀키는 자료 요청 문서에 쓰지 않습니다. 서버의 비밀환경변수로 설정합니다.

## 운영 연결 순서

1. 현재 운영 스키마와 프로젝트 상태를 확인한 뒤 `supabase/migrations/20260930170000_procurement_foundation.sql`을 적용합니다. 기존 업무 테이블의 데이터는 변경하지 않습니다.
2. 새 스키마의 타입을 재생성합니다. 현재 신규 테이블 어댑터는 `server.ts`에 격리되어 있습니다.
3. 서버에 아래 환경변수를 연결합니다. 오너뷰의 Resend 발신 설정을 재사용하되 Edge Function 비밀값과 Next 서버 환경변수는 별도 연결 여부를 확인해야 합니다.

| 환경변수 | 목적 |
|---|---|
| `G2B_SERVICE_KEY` | 공공데이터포털 Decoding 인증키 |
| `RESEND_API_KEY` | 오너뷰 메일 계정의 발송 키 |
| `RESEND_FROM_EMAIL` | 검증된 발신 도메인의 발신 주소 |
| `PROCUREMENT_COMPANY_ID` | 자동화 대상인 모티브의 오너뷰 회사 UUID |
| `PROCUREMENT_CRON_SECRET` | 예약 실행 인증용 32자 이상 비밀값 |
| `PROCUREMENT_G2B_VERIFIED` | 실제 공고·첨부·날짜·금액·정정/취소 응답 검증 후에만 `true` |
| `PROCUREMENT_SCHEDULER_ENABLED` | 예약 실행기 연결 확인 후에만 `true` |

4. 승인된 실제 API 키로 검색어 `홍보`의 목록·총건수·페이지·차수·날짜·금액·첨부 응답을 검증합니다. 어댑터 명세와 실제 응답이 다르면 활성화 전에 수정합니다.
5. `/procurement`에서 회사정보와 파일 목록이 해당 회사 자료인지 확인하고 검색어·수신자·시각을 저장합니다.
6. 수동 수집 → 원문 첨부 → 증빙 등록 → 평가 → 진행 → 초안 생성까지 운영 로그인으로 확인합니다.
7. 메일 본문·수신자를 확인한 뒤 시험 발송하고 실제 수신·반송 여부를 확인합니다. 공급사 성공 응답만으로 수신을 단정하지 않습니다.
8. 예약 실행기가 매시간 `GET /api/procurement/worker`를 `Authorization: Bearer <비밀값>`으로 호출하도록 연결합니다. URL에 비밀값을 붙이지 않습니다. 현재는 **매일, 한국시간 기준, 설정 시각 이후 미발송 요약을 보내는 방식**입니다.
9. 실제 수집·메일 실패와 실행 중단 재시도를 확인한 뒤 화면의 자동수집·자동메일을 켭니다. 초기값은 모두 OFF입니다.

현재 프로젝트 brain 기록에 `UNSYNCED`가 남아 있습니다. 운영 반영 단계 전에 현 상태를 확인·동기화해야 합니다. 로컬 구현과 격리 검증은 완료할 수 있습니다.
