## 1. 그들이 실제로 쓰는 문서 뼈대

한 잡(job)당 엑셀 한 권. 시트가 곧 사고 단계다.

| 시트 | 하는 일 |
|---|---|
| 기획개요 | 요청 원문 + 의도/목표 + **버전 이력(1.0 → 1.1 …)** |
| 회의내용 | 일자·회의명·**참석자별 발언을 각자 칸에** 그대로 |
| 변경내역 | 어느 시트가 왜 바뀌었나 · 요청자 · 합의 경로 · 결정 인원 · 버전 |
| 분석 | AS-IS · History · **상세분석(자문자답)** · 방향 |
| 결정사항/최종 | 번호 붙은 결론 + AS_IS ▶ TO_BE 표 |
| 체크리스트 | 68행짜리 누락 방지 목록(권한·양식·이력·발송·업로드·다운로드·마이그레이션·국가별…) |
| 기능리스트 / 속성명세 | 바뀌는 기능·속성을 **신규/수정만** 표로 |
| 업무관계도 | 이 업무에서 파생되는 업무 도식 |
| 마이그레이션 | 기존 데이터를 새 규칙으로 어떻게 옮길지 Case별 |
| 서버/UI 기능제공방안 | 기능별 **변경/유지/신규/제거** + Mig 여부 |

핵심은 시트 개수가 아니라 **분석 → 결정 → 누락점검 → 이관** 이 분리돼 있다는 점이다.

## 2. 분석 시트가 진짜 무기다 — 자문자답으로 전제를 캔다

741(카드매입 부가세) 분석 시트를 그대로 옮기면:

```
상세분석
  무엇을 기준으로 부가세가 계산되어야 하는가
    - 기존에는 결제된 부가세 금액을 그대로 넘겼고, 현재는 유형에 따라 재계산한다
  부가세 신고 기준이 무엇일까
    - 사용자가 부가세를 입력하는 이유는 신고하기 위함이다
    - 부가세는 증빙에 기반한 신고라서, 영수증/매출전표에 찍힌 값을 기준으로 해야 한다
    - 다만 단말기 계산도 100% 신뢰할 수 없고 공제/불공제 확인이 필요하다
  유형 기준으로 계산되어야 하는 경우가 있을까?
    - 접대비처럼 공제하지 않는 지출이면 유형에 따라 0으로 찍혀야 한다
    - 삼성/롯데(개인)는 부가세를 아예 안 주므로 재계산이 필요하다
  사용자가 확인할 때 무엇을 기준으로 보는 게 편할까
    - 가맹점 기준으로 볼 것이다. 다만 한 거래에 과세/면세가 섞이면 거래처만으론 못 정한다
▶ 실제 결제금액과 유형에 따라 반영될 금액을 같이 보여 주고 사용자가 고칠 수 있어야 한다
▶ 부가세유형은 거래처와 상대계정 기준으로 저장되어야 한다
```

배울 점 넷:

1. **"무엇을 기준으로 X 되어야 하는가"** 를 먼저 묻는다. 화면·버튼 이야기가 아니라 **판단 기준**을 캔다.
2. **사용자가 왜 그걸 하는지까지 내려간다** — "부가세를 입력하는 이유는 신고하기 위함" → 그래서 **증빙이 기준**이라는 결론이 나온다. 기능이 아니라 목적에서 규칙이 도출된다.
3. **반례를 스스로 만든다** — "유형 기준이어야 하는 경우가 있을까?" → 접대비·삼성개인카드. 반례가 곧 예외 설계가 된다.
4. **못 푸는 경우를 인정하고 적는다** — "과세/면세가 섞이면 사용자가 직접 입력할 수밖에 없다." 억지로 자동화하지 않는다.

### 생각이 흔들리는 과정을 지우지 않는다

741 '방향' 시트에는 이런 문장이 그대로 남아 있다.

> 그럼 최초 부가세유형은 뭘로 해줘야 하지?
> 근데 그렇게 되면? 부가세유형을 변경하면 부가세가 다시 재계산됨..ㅋㅋ
> 부가세유형대로 계산할래, 부가세 정보를 불러올래 둘 중 하나만 해야될 듯?

정리된 결론만 남기면 **왜 다른 안을 버렸는지**가 사라진다. 다음 사람이 같은 길을 다시 판다.
오너뷰 문서·커밋도 **버린 안과 버린 이유**를 남긴다.

## 4. 결론을 내는 방식 — 번호 · AS_IS ▶ TO_BE · 예외표

739(중복 기표 방지) 결론:

> **왜 다른 탭에서 전표 처리를 하는가**
> - 사용자는 '미반영 건을 처리해야 한다'고 인지하지 않는다. 보통 **'이번 달 카드 전표 처리'** 를 목적으로 들어온다.
> - 그래서 전체 내역에서 조건을 걸어 일괄 처리하고, 그때 이중 기표가 난다.
> ▶ 밀어주기 시 from 에 to 번호를 넣을 때 **이미 값이 있으면 알럿**

사용자의 **의도(월 단위 마감)** 와 화면의 **전제(미반영 탭에서 처리)** 가 어긋난 지점을 짚어
UI 안내가 아니라 **저장 경로에 체크**를 넣는 결론으로 간다. 교육이 아니라 구조로 막는다.

728은 결론을 이렇게 적는다.

```
1️⃣ 파생단위는 root의 라인별로 한다
2️⃣ 연결관계 데이터도 라인:거래로 쌓는다   (AS_IS 표 ▶ TO_BE 표)
3️⃣ 5.6 개발 완료 이후 적용한다            (착수 시점)
4️⃣ 기존 데이터도 모두 마이그레이션한다     (전표일자번호는 새로 채번)
```

**결론마다 ①규칙 ②데이터 형태 변화 ③적용 시점 ④기존 데이터 처리**가 붙는다.

741의 예외 설계는 값 하나하나를 표로 못박는다.

```
부가세유형   기본: 직접입력(카드매입)
             예외1: 거래업체명에 '주유소' 포함 → 카드매입(불공)
             예외2: 조건없음 → 정보불러오기(다중형식)
부가세       기본: 정보불러오기(부가세)
             예외1: 부가세유형 = 빈값 → 빈값
             예외2: 재계산여부 = Y → 총금액 - 총금액/(1+부가세율)
색 규칙: 빨강=기본설정값 / 파랑=회사코드별 마이그레이션 / 검정=사용자가 직접 설정
```

**기본값 · 예외 · 예외의 순서 · 누가 정하는 값인지**까지가 한 세트다.

## 5. 오너뷰 실행 규칙 — 기능 만들기 전에 이 순서로

문서를 엑셀로 만들자는 게 아니다. **순서와 질문을 가져온다.** S 티어 작업도 ①②⑥은 한다.

### ① History — 지금 왜 이 모양인가 (5분)
- `git log`·주석 날짜·기존 기획서를 먼저 본다. **"그때는 왜 맞았나"** 를 한 줄로 적는다.
- 이 단계 없이 "버그다" 라고 부르지 않는다.

### ② 상세분석 — 자문자답 3개 이상
반드시 포함할 질문:
- **무엇을 기준으로 판단되어야 하는가?** (계산 근거·정렬 기준·표시 기준)
- **사용자는 이걸 왜 하는가?** 그 목적에서 규칙이 나오는가?
- **반대 경우가 있는가?** (반례 → 예외 설계)
- **자동으로 못 푸는 경우는 무엇인가?** → 그건 사람이 하게 두고 **그 사실을 화면에 적는다.**

### ③ 결정 — 번호 + 네 가지 세트
결론마다 **규칙 / 데이터 변화(AS_IS ▶ TO_BE) / 적용 시점 / 기존 데이터 처리**.
기본값·예외를 쓸 땐 **예외 순서**와 **누가 정하는 값인지**(기본값·회사설정·사용자)를 같이 적는다.

### ④ 누락 점검 — 오너뷰판 체크리스트
이카운트 68행을 우리 크기로 줄인 것. 해당 없으면 "해당없음"이라고 **적는다**.

- [ ] **용어** — 화면에 나갈 정식 명칭을 정했나 (사장님 규칙: 비전문용어·단순어 우선)
- [ ] **권한** — `member_permissions` 키가 필요한가. 메뉴가 갈라지면 **기존 권한자에게 이어 줬나**
- [ ] **RLS** — 새 표/칸이 RLS를 타는가. 회사 경계가 지켜지나
- [ ] **역할** — owner/admin/employee/partner 각각 무엇이 보이나 (직원 화면 동일 적용)
- [ ] **빈 상태·0건** — 처음 쓰는 회사에서 무엇이 보이나
- [ ] **경계값** — 음수(수정계산서·환불·취소), 0, 소수점, 단수차이
- [ ] **중복 실행** — 두 번 누르면? 이미 처리된 건을 또 처리하면? (739의 교훈)
- [ ] **마감/잠금** — 마감된 달, 이미 발행된 문서
- [ ] **기존 데이터** — 마이그레이션 규칙. 기본값으로 채우면 **보이는 값이 달라지지 않는가**
- [ ] **다른 화면 파급** — 이 값을 읽는 화면 목록(손익·부가세·원장·대시보드)
- [ ] **외부 전송** — 국세청·이메일·알림으로 나가는 값이 바뀌는가
- [ ] **인쇄·엑셀·PDF** — 새 칸이 여기에도 나와야 하나
- [ ] **모바일 폭** — 격자/표가 좁은 화면에서 어떻게 되나
- [ ] **되돌리기** — 잘못 눌렀을 때 되돌릴 수 있나 (사장님 규칙)

### ⑤ 파급 확인 — "이 값을 누가 읽는가"
새 칸·새 계산을 만들면 **읽는 쪽을 전부 grep** 해서 목록으로 적는다.
(예: `entry_kind` 추가 → 전표 목록·부가세 집계·원장·마감 체크)

### ⑥ 커밋 메시지에 남길 것
- **왜 이 모양이었나(History)** → **무엇을 바꿨나** → **버린 안과 이유** → **검증 결과(숫자)**
- 이 저장소의 기존 커밋들이 이미 이 형식이다. 계속 지킨다.
