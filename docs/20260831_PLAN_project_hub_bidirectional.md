# 프로젝트 메뉴 신규 기획 v2.6 — 구조 단순화 + 양방향 허브 (2026-08-31)

사장님 요청: "재고·회계·인사 등 회사에서 발생하는 업무를 프로젝트로 종합 관리하고,
성과·현황을 한번에 보고 싶다. 프로젝트에서 입력하면 재고·회계에 전표·문서가 자동 생성되고,
다른 메뉴에서 입력한 것도 프로젝트로 가져오는 **양방향**. 사용이 편하고 쉬워야 한다.
대규모로 바뀌어도 좋다 — 목업으로 먼저 테스트."

동작 목업 (v2.1): https://claude.ai/code/artifact/beec24a2-3c10-43e7-a048-4e4609001efe

  지금 프로젝트 메뉴가 굉장히 어렵고 복잡한 느낌"* → 구조 단순화를 0번 결정으로.
- **v2.1** (08-31, 사장님 지적 둘): ① *"'모인 것' 등 모호한 표현은 회사·업무에서 쓰는 말로 전부

  작동하는지 점검"* → 작동 점검 절 신설, 구멍 3개를 보완 결정으로 추가.
- **v2.2** (08-31, 사장님 지적 둘): ① *"프로젝트를 누르면 진행현황·관리현황·담당자·성과가
  일목요연하게 정리되는 것까지 기획됐나?"* → 상세 머리에 **현황 판 네 칸**(결정 0-6) 신설 —

  아니라 '고른 것이 구조를 영구히 결정하는 것'이었다. **시작 꾸러미**(결정 0-7)로 되살림 —
  고르면 초기 내용이 채워지고, 구조는 어느 것을 골라도 같은 한 장.
- **v2.3** (08-31, 사장님 강조): *"견적서·주문서를 보내고, 상대가 승인하면 계약서가 만들어지고,
  서명하면 판매전표·회계전표가 자동 발행되고 — 상대가 반려나 수정을 하면 다시 우리가 승인하는

## 용어 결정 (v2.1) — 화면에 나가는 말은 전부 회사에서 쓰는 말로

| 이전(초안) 용어 | 확정 용어 | 이유 |
|---|---|---|
| 모인 것 | **증빙·문서** | 전표·통장·카드·계산서·계약서·결재·발주서 — 회사에서 부르는 이름 그대로 |
| 연결 후보 | **연결 제안** | 앱 표준 'AI 제안' 언어와 일치(채워만 주고 확정은 사람) |
| 적기 | **입력** | 격식체 규칙(2026-08 구어체 정리, f0446906) |
| 줄 | **항목** | "줄"은 구어체 — ERP 표준어 |
| 성격 (칩) | **구분** | ERP 에서 가장 익은 말 |
| 돈 (탭) | **매출·지출** | 안의 항목 구분(매출/지출)을 그대로 탭 이름으로 |
| 기록 (탭·칩) | **회의·메모** | 실제 담기는 것(회의록·메모)을 그대로 |
| 계획 (금액 칸) | **예정** | 예정 금액 vs 확정 금액 — 지출(예산)·매출(청구 예정) 양쪽에 자연스러움 |
| 확정 (금액 칸) | **확정(장부)** | 장부에서만 온다는 출처를 이름에 명시 |
| 장부 연결 (칸) | **증빙** | 어떤 증빙이 붙었는지 — "세금계산서·카드·통장 입금·지출결의 초안" |
| 무시 (버튼) | **아님** | 판단("이 프로젝트 것이 아니다")을 그대로 말함 |
| 서식 | **양식** | 앱 전반에서 이미 '양식'(결재 양식·회사 양식) 사용 중 |

원칙: 새 개념어를 만들지 않는다 — 이미 회사·앱에서 쓰는 말만 재사용. 이후 화면·코드 라벨·
route-labels 전부 이 표를 따른다.

## ② 자문자답

**0. 무엇을 기준으로 '쉽다'고 판단하는가?**
- ⓐ 처음 배울 개념 수 ⓑ 입력까지 결정 횟수 ⓒ 같은 일을 하는 방법이 하나인가.
- AS-IS: 개념 30+ · 결정 3번 · 할 일 적는 곳 3곳. TO-BE: **개념 9 (탭 4+구분 4+입력줄 1) · 결정 1번 · 한 가지 일 = 한 곳.**

**1. 사용자는 프로젝트에서 실제로 무엇을 하는가?**
- 실측 110행을 구분으로 접으면 셋: **할 일**(진행·검수·일정·계약만기 58) · **매출·지출**(36) · **회의·메모**(16).
- 템플릿 8종은 이 셋의 변주였다. ▶ 축을 템플릿(일의 종류)이 아니라 **구분(항목의 종류)** 으로.

**2. "데이터가 생기면 자리가 열린다"는 왜 버리나?**
- 열림/닫힘 규칙 자체가 학습 대상이고, "입력할 곳"이 안 보이면 입력하지 않는다
  (실측: 안 열린 자리 전부 0 = 영영 0). ▶ **항상 같은 탭 4개** — 예측 가능성이 빈 화면 감추기보다 중요.

**3. 반대 경우 — 전용 화면이 정말 필요한 일은 없나?**
- 회의록(안건·결정·후속)·외부 요청 접수 폼은 표 한 줄로 안 접힌다.
  ▶ 폐지가 아니라 **항목 상세 팝업 속으로** — 겉(목록·입력)은 하나, 속만 구분별로 깊어진다.

**4. 자동으로 못 푸는 것 (유지)**
- 여러 프로젝트에 걸친 비용 배부 → 사람이 나눠 입력(화면에 명시).
- 예정(입력 금액) vs 확정(장부 금액) → 동기화하지 않고 나란히.

**5. (v2.2) 템플릿 선택은 왜 편했고, 무엇이 문제였나?**
- 편했던 것: "행사 준비"를 고르면 **무엇부터 적어야 할지가 채워져 나온다** — 빈 화면 공포 제거.
- 문제였던 것: 고른 순간 **화면 구조가 갈라지고**(7가지 전용 UI) 이후 바꿀 수 없었다.
  7/30 실측의 교훈("수익형으로 만든 30개가 진행률을 영구히 못 썼다")도 같은 뿌리.
- ▶ 선택의 편의(초기 내용)는 살리고 구조 결정력만 제거한다 = **시작 꾸러미**.
  꾸러미 이름은 표 이름이 아니라 **하려는 일 이름**으로(사장님 표현 그대로 "하고 싶은 일에 따라").

**6. (v2.2) 프로젝트를 열면 무엇이 3초 안에 읽혀야 하나?**
- 대표가 확인하는 순서: ①어디까지 왔나(진행) ②누가 하고 있나(담당) ③돈이 어떻게 되나
  ④남는 장사인가(성과). 이 넷이 탭을 누르기 전, 머리에서 끝나야 한다.
- v2.1 머리는 ③④만 있었다(계약·예정·확정·마진). ①②가 탭 안에 숨어 있었다 → 현황 판 네 칸.

**7. (v2.4) 작업 관리 기능 9종을 더하면서 어떻게 '개념 9개'를 지키나?**
- 원칙: **탭·구분·화면을 늘리지 않는다.** 9종 전부 이미 있는 그릇에 들어간다 —
  ⓐ 항목의 속성(팔로워·반복·종속·마일스톤·비공개)과 항목 상세 팝업(하위작업)
  ⓑ 목록의 표준 부품(일괄 처리 = 조회 표준 SelectionBar)
  ⓒ 기존 메뉴의 확장(내 작업 = 기존 '일정/할 일' 메뉴)
  ⓓ 바탕 기술(실시간 = Supabase Realtime, 채팅에서 이미 사용).
- 처음 쓰는 사람은 여전히 "내용 쓰고 구분 칩" 만 배우면 된다 — 심화 속성은 안 쓰면 안 보인다.

**8. (v2.4) '자동 일정 조정'은 어디까지 자동인가?**
- 선행 작업이 늦게 끝나 후행 시작이 불가능해지면 → 후행 **기한을 자동으로 민다** + 담당·팔로워
  알림 + 원클릭 되돌리기. 여기까지는 기계가 낫다(사람은 밀린 것을 잊는다).
- 단, **고객과 약속한 날짜(마일스톤·계약 납기)는 자동으로 밀지 않는다** — 시스템이 약속을 바꿀
  수는 없다. 경고만 띄운다("이대로면 납기 9/30 을 지킬 수 없습니다"). 못 푸는 것은 사람에게.

## ②-1 작동 점검 (v2.1) — 구분 4종이 기존 업무를 전부 받아내는가

기존 템플릿 8종의 **목적 동작**(8/20 점검에서 확인된 "적기·챙기기")을 하나씩 대조:

| 기존 템플릿 (행) | 목적 동작 | 새 구조에서 | 판정 |
|---|---|---|---|
| 할 일·진행 (18) | 누가 언제까지 + 상태 | 할 일 항목(담당·기한·상태) | ✅ |
| 매출 흐름 (23) | 건별 금액·입금 + 견적→계약→계산서 체인 | 매출 항목 + 상세 팝업의 문서 체인 | ✅ |
| 예산·지출 (13) | 예산 대비 집행, 구분별 | 지출 항목(예정=예산, 확정=장부) | ✅ |
| 회의·결정 (16) | 안건·결정·후속 양식 | 회의·메모 항목 + 상세 팝업 양식, 후속→할 일 보내기(기존 기능) | ✅ |

  | 경우 | 판정 기준 (누가 정하나) | 흐름 |
  |---|---|---|
  | ① 결재 정책 해당 | 회사 결재 정책: 유형(지출·발주·계약 발송…)+금액 문턱. 회사설정 값 | **결재 상신 → 다단계 승인 → 승인 완료 시점에 장부·전표 반영/발송 실행.** 반려 시 반영 없음, 항목에 반려 사유 |

  정책이 뚫린다). 알림은 기존 결재 알림 재사용.

- **프로젝트 유일 관문 / 거래처 자동 확정 / 예정↔장부 동기화** — v1 과 동일 사유.

## 단계 (목업 승인 후)
1. **1단계**: 새 상세 한 장(현황 판 4칸 + 탭 4 + 입력줄, 상태 이름·기간 포함) + 시작 꾸러미 생성 흐름 + 마이그레이션 — L 티어, db-architect 선행
2. **2단계**: 증빙·문서 탭 + 연결 제안 + deal_id 확장(결정 4) + 낡은 문구 정리
3. **3단계**: 지출·매출→초안(발주서 포함) + 밖 메뉴 저장 팝업 프로젝트 칸(제안+학습)
   + 거래처 핑퐁(결정 6: 수정 요청 왕복 → 계약 자동 생성 → 서명 시 전표 자동 발행)
4. **4단계**: 목록 현황판 + 항목 팝업 심화(회의록 양식·문서 체인·요청받기) + 달력 보기
5. **5단계**: 내 작업 화면(일정/할 일 확장 + 비공개 파이프라인) + 실시간 협업(Realtime·presence)
6. **6단계**: 자동화 규칙 엔진(레시피형 — 반복·종속 조정 흡수) + 작업표→인건비→청구 연동
